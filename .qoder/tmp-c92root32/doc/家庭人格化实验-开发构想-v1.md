# 家庭人格化实验 - 开发构想

## 背景

DCD 决策批准"家庭人格化实验"后，我们做了第一阶段：MA 自动生成自我日记。

## 现状

### 已完成
- MCP 工具：`write_self_diary` / `read_self_diary` / `generate_self_diary`
- 定时任务：每天 23:00 自动生成日记
- 日记写入 staging，永不自动晋升
- 隐私：只喂脱敏摘要（时间+房间+活动），不喂原始画面/语音

### 实验结论
**日记生成效果不理想**，原因：
1. **events 表里有意义的事件太少**——大部分是温度/湿度/电量这种传感器读数，门/灯/人/设备开关这种有意义的事件只有凌晨那几分钟
2. **LLM 只能机械地复述摘要**——严格遵循"不许编造"的规则后，日记变成了"00:04 厨房灯亮了。00:05 客厅开关动了。之后没有记录。"
3. **没有真正的"人格化"感觉**——每天的结构都一样："昨天我说…→ 列设备 → 这些是全部 → 昨天我说…"

## 正确架构

```
┌─────────────┐     MCP      ┌─────────────┐
│  豆包管家    │ ◄──────────► │  memory-agent │
│  (交互层)    │              │   (数据层)    │
└─────────────┘              └─────────────┘
       │                            │
       │ 聊天接口                    │ events 表
       │ LLM 生成自然语言            │ 行为洞察
       │ 主动发起对话                │ 人物画像
       │                            │ 视觉识别
```

### 职责划分

**memory-agent（数据层）**：
- 每天自动生成日记（机械化部分）
- 提供行为洞察 API
- 提供人物画像 API
- 提供 `read_self_diary` MCP 工具

**豆包管家（交互层）**：
- 通过 MCP 调 MA 的行为洞察
- 把日记内容读出来，在聊天里跟用户说
- 主动发起对话："今天你客厅待了 8 小时，比昨天多了 2 小时"
- 生成自然语言，不是机械复述 events

## 下一步迭代

### 短期（当前）
- 日记先这样跑着，每天自动生成
- 豆包管家通过 MCP 能读出来就行
- 等采集恢复了有了更多事件，日记内容自然就丰富了

### 中期
- **专门适配行为洞察模板**：现在的模板太少了，要加"每日家庭总结"这种专门适配人格化场景的模板
- 用行为洞察代替原始 events 生成日记："客厅是主场"、"凌晨 1-2 点才睡"这种，比"00:04 厨房灯亮了"有意义多了
- 豆包管家加"每日总结"技能：每天晚上调 MA 的行为洞察，在聊天里跟用户说今天的观察

### 长期
- 多模态融合：把视觉识别结果（谁在家、在哪个房间）融入日记
- 情绪感知：VLM 识别情绪，融入日记
- 主动规则：根据日记内容自动触发提醒（"你已经连续 3 天凌晨 1 点后睡了"）

## 隐私保护
- 日记只喂脱敏摘要（时间+房间+活动类型）
- 不喂原始画面、原始语音
- 日记写入 staging，永不自动晋升
- 用户可以随时查看和删除
