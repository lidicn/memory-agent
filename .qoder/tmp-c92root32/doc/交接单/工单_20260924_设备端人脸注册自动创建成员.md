# 工单：设备端人脸注册应自动创建成员，而非返回 400

**发起方**：TVPilot（ArcFace 电视节点）
**日期**：2026-09-24
**优先级**：P1
**状态**：待 MA 开发修复

---

## 问题描述

ArcFace 电视节点注册新人脸后，调用 `/api/face/node/lib` POST 上传特征，MA 返回 400 错误，导致设备端无法自动注册新人脸。

## 复现步骤

1. MA 数据库中不存在名为 `用户_0924_1521` 的成员
2. ArcFace 本地注册新人脸，name=`用户_0924_1521`
3. ArcFace 调用 `POST /api/face/node/lib`，body: `{"name": "用户_0924_1521", "face_feature": "<base64>"}`
4. MA 返回 `400 {"error": "需提供 member_id 或可识别的 name"}`

## 根因定位

**文件**：`src/memory_agent/api/face_routes.py:98-113`

```python
async def face_node_lib_post(request: Request):
    ...
    member_id = _resolve_member_id(rt, body.get("member_id"), body.get("name"))
    if not member_id:
        return error("需提供 member_id 或可识别的 name")  # ← 这里返回 400
    ...
```

**`_resolve_member_id`（第 42-53 行）**：
- 如果传了 `member_id`，直接返回
- 如果只传了 `name`，在已有成员中查找
- **如果找不到，返回空字符串** → 触发上面的 400 错误

## 设计缺陷

设备端（ArcFace）是人脸注册的入口，用户在电视上注册新人脸时，MA 数据库里还没有这个成员。当前设计要求**先在 WebUI 手动创建成员，才能上传特征**，这不符合实际使用流程。

正确流程应该是：
1. 用户在电视上注册新人脸
2. ArcFace 提取特征，上传到 MA
3. **MA 自动创建成员（如果 name 不存在）**，然后关联特征

## 修复方案

在 `face_node_lib_post` 中，当 `name` 不存在时，自动调用 `rt.store.create_member(name)` 创建成员，然后再上传特征。

**建议修改（face_routes.py:108-110 附近）**：

```python
member_id = _resolve_member_id(rt, body.get("member_id"), body.get("name"))
if not member_id:
    # 设备端自动注册：name 不存在则自动创建成员
    name = (body.get("name") or "").strip()
    if name:
        new_member = rt.store.create_member(name)
        member_id = new_member.get("id", "")
    if not member_id:
        return error("需提供 member_id 或可识别的 name")
```

## 验收标准

1. MA 中不存在名为 `测试_自动创建` 的成员
2. 调用 `POST /api/face/node/lib`，body: `{"name": "测试_自动创建", "face_feature": "<base64>"}`
3. 返回 200，且 MA 数据库中新增了该成员
4. 再次调用 `GET /api/face/node/lib`，能看到该成员

## 影响范围

- TVPilot 侧：ArcFace uploadFeature 调用成功，新人脸自动同步到 MA
- MA 侧：设备端可以自动创建成员，无需 WebUI 手动干预
- 兼容性：不影响已有成员的上传流程（name 存在时走原逻辑）
