# 交接卡：v0.5 记忆统一入库（source / confidence）

> 设计依据：`docs/架构设计_MA对外接口与设备身份层.md`（需求 C）
> 前置版本：v0.2 实体身份层、v0.3 对外查询接口、v0.4 MQTT 实时推送

## 一句话
给记忆库加 **`source` 来源字段**，把「豆包管家生态」与「MA 原生」记忆统一进同一张 `agent_memories` 表（不再有平行表），并用既有的 `trust` 字段作为 **confidence**，让检索与列表可按来源过滤、低置信 LLM 摘要可被标注隔离，不再污染高置信行为事实。

## 2. 语义说明（关键设计决策）

| 维度 | 字段 | 说明 |
|------|------|------|
| **来源 / provenance** | `source`（新增） | `ma` = MA 原生记忆；`butler` = 豆包管家生态写入；可扩展 `vision` / `manual` 等 |
| **置信度 / confidence** | `trust`（既有复用） | 0~1 区间，参与检索重排 `final = 0.7*sim + 0.3*((trust+1)/2)`，晋升闸门也看它 |

> 选择**复用 `trust` 而非新建 `confidence` 列**：避免冗余 schema，且 `trust` 已贯穿晋升/检索/反馈闭环。统一描述为一句话——
> 「`source` 回答**这记忆从哪来**，`trust` 回答**可信度多高**」。

**低置信 LLM 摘要的隔离机制**（回应需求 C）：
1. 写回时即带 `source`（如 `butler`），落库后可被检索按来源过滤；
2. 写回默认 `state=staging`，**永不自动进 live**（既有护栏），需 `promote` / sweep 晋升；
3. 晋升需满足「高置信佐证 insight」或「跨 ≥N 天观测」——管家低置信摘要很难自动升级，天然污染不到 live 检索；
4. 检索侧可 `retrieve(question, source="ma")` 只召 MA 原生高置信事实，或 `source="butler"` 单独看管家摘要。

## 3. 接口变化

```bash
# 管家生态写入（带来源标记）
curl -X POST http://<MA>:8086/api/agent/memories \
  -H "Authorization: Bearer <JWT>" -H "Content-Type: application/json" \
  -d '{"text":"孩子一般 22 点后还在玩电脑","source_refs":["insight:2026-x"],
       "source":"butler","dry_run":false}'

# 只看管家生态记忆
GET /api/agent/memories?source=butler

# 检索时只召回本服务原生记忆（隔离低置信摘要）
POST /api/agent/memories/retrieve {"question":"...","source":"ma"}
```

## 5. 已知风险与偏差

| 项 | 说明 |
|----|------|
| **「平行表」的实际落地是集成动作，非本版本代码** | 本版本在 MA 侧把记忆库改造为「单表 + source 标签」的**统一形态**。要让管家生态的记忆真正汇入，需在 doubao-butler 项目中调用 MA 的 `/api/agent/memories`（带 `source="butler"`）。MA 已就绪，跨项目接线属部署/联调范畴（与 v0.4 生态联调同类）。 |
| **存量数据默认归入 `ma`** | 迁移 `ALTER` 给旧行补 `source='ma'`。若历史上有管家写入的记忆此前未标记，会被视为 `ma` 原生——这是保守且安全的默认（不会误标低置信）。如需纠正，可按 `session_id` 批量回填 `source='butler'`（一条 SQL）。 |
| **chroma 镜像重建** | `source` 仅进 SQLite 主表与 chroma 元数据镜像。已存在 live 的旧记忆在 re-embed 前其 chroma 元数据不含 `source`；新写入/晋升的会带。检索按 source 过滤对「尚未重建镜像的旧记忆」可能漏过滤——属可接受的渐进一致（重建镜像可 `reconcile` 触发）。 |
| **未做来源级写入鉴权** | 目前任何持 JWT 的调用方都能以任意 `source` 写入；若担心恶意标注，后续 v0.6 可限定 `source` 取值白名单或按 token 派生来源。 |

---

## 6. 合并影响

- 仅新增一列（带默认 `ma`），**对既有部署零破坏**：旧行自动补 `ma`，旧调用不传 `source` 仍写 `ma`。
- 既有记忆写入/晋升/检索逻辑**完全不变**，仅多了可选的 `source` 维度。
- 无新增第三方依赖。
