## 1. 项目简介

**memory-agent（Memory Agent）** 是一个家庭行为记忆与洞察系统：采集 Home Assistant 设备事件、Node-RED 自动化执行结果，结合 Redis（去重/缓冲）、Chroma（向量语义检索）、MariaDB（HA 历史库）、内置 LLM，提供：

- 家庭行为节律 / 设备用量 / 异常行为洞察
- 自然语言对话（含工具调用、会话记忆）
- 对外协议：**HTTP API** + **MCP**（给 AI 客户端） + **ACP**（Agent Client Protocol，给 agent 编排端，如 autoflow）

---

## 2. 技术栈与组件

| 组件 | 作用 | 容器服务名 |
|------|------|-----------|
| FastAPI / Starlette | 主 API + MCP + ACP 网关 | `memory-agent` |
| Redis | 事件去重 / 缓冲 | `redis` |
| Chroma | 行为向量库 / 语义检索 | `chroma` |
| MariaDB | Home Assistant 历史库（只读取） | `ha-mariadb`（外部/既有） |
| Node-RED | 自动化执行后端 | `nodered` |
| Caddy | 反向代理 + TLS | `caddy` |
| 内置 LLM | OpenAI 兼容接口（默认 deepseek） | 进程内 |

## 6. 关键接口

| 端点 | 协议 | 说明 |
|------|------|------|
| `/api/*` | HTTP JSON | 行为洞察 / 会话 / 设备用量等 REST |
| `/mcp` | MCP（JSON-RPC + SSE） | 给 AI 客户端（Claude Desktop / CodeBuddy 等） |
| `/acp` | ACP（JSON-RPC over HTTP + SSE） | 给 agent 编排端（autoflow / 其他 ACP client） |
| `/acp` (GET) | HTTP | 服务描述（需 Bearer token） |

ACP 方法（本项目自定义子集）：`initialize` / `session.new` / `prompt`（非标准 `agent/initialize` 风格）。

## 7. 近期重要修复（2026-08-13）

### 问题

`GET/POST /acp` 全部返回 500：`TypeError: _ACPRootApp.__init__() takes 1 positional argument but 4 were given`。

### 根因

`src/memory_agent/app.py` 中精确路径路由把 ASGI **类**当 endpoint 传给 Starlette `Route`：

```python
routes.append(Route("/acp", endpoint=_ACPRootApp, ...))   # 传了「类」
```

Starlette `Route.__init__` 对「类 endpoint」分支是 `self.app = endpoint`（直接把类当 ASGI app 存着），`route.handle` 调 `self.app(scope, receive, send)` 时等于 `_ACPRootApp(scope, receive, send)`——用 3 个参数去**构造**类，触发上述报错。

### 修复

ASGI 类 endpoint 必须传**实例**（Starlette 直接调其 `__call__(scope, receive, send)`）：

```python
routes.append(Route("/acp", endpoint=_ACPRootApp(), ...))   # 传「实例」
routes.append(Route("/mcp", endpoint=_MCPRootApp(), ...))    # 同构隐患一并修
```

### 验证

容器重启后，`initialize` / `session.new` / `prompt`（SSE 流式）全链路通过，`prompt` 末条 `status:"completed"` 且产出真实行为洞察文本。验证命令见第 9 节。

## 9. ACP 验证清单（接手后回归用）

```bash
TOKEN=acp_xxx                 # WebUI 生成的 kind=acp token
H=http://<HOST>:8086          # 或 https://<域名>/acp

# 1) 探活
curl -s $H/acp -H "Authorization: Bearer $TOKEN"
# 2) initialize
curl -s -X POST $H/acp -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
# 3) session.new
curl -s -X POST $H/acp -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"session.new","params":{}}'
# 4) prompt 流式 SSE（取上一步 sessionId）
curl -N -X POST $H/acp -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"jsonrpc":"2.0","id":3,"method":"prompt","params":{"sessionId":"<SID>","messages":[{"role":"user","content":"总结本周家庭作息"}]}}'
```

判定：第 4 步持续吐 `session_update`，末条 `status:"completed"` 且 `content` 含 `type:"text"` 最终答案即正常。

- 容器/服务名 `memory-worker` → `memory-agent`（`docker-compose.yml` / `Caddyfile` / `scripts/gen-certs.sh` / mcp `SERVER_NAME`）
- Python 包 `memory_worker` → `memory_agent`（含 `Dockerfile` CMD、`pyproject.toml` 的 `packages`/`[project.scripts]`、2 处绝对导入、`tests`/`scripts`）
- SQLite `data/memory_worker.db`(+`-shm`/`-wal`) → `memory_agent.db`，并同步 `store.py` / `config.py` / `data/config.json` 的 `db_path`（**数据不丢**）
- `ha_db_user` 默认值 `memory_worker_ro` → `memory_agent_ro`（`config.py` / `config.json` / `docker-compose.yml`）
- `data/config.json` 的 `jwt_secret` 默认值 `memory-worker-secret-key-…` → `memory-agent-secret-key-…`（被 `.env` 的 `JWT_SECRET` 覆盖，无实际影响）

### 11.2 NAS 上必须手工执行（CodeBuddy 改 NAS 文件夹名会闪退，故目录改名由人来做）

**第 1 步：在 Windows 资源管理器 / SMB 把运行目录改名**

```
\\192.168.2.200\docker\memory-worker  →  memory-agent
（对应 NAS 真实路径 /vol1/1000/docker/memory-agent）
```

**第 2 步：SSH 进 NAS，清理旧容器并重建启动**

```bash
# 旧容器项目名是 memory-worker，目录改名后 compose 认不到，必须手动清
docker rm -f memory-worker
docker network rm memory-worker_default 2>/dev/null

# 进新目录：重建镜像并只拉起主服务（不要启动 caddy，避免 443 端口冲突）
cd /vol1/1000/docker/memory-agent
docker compose up -d --build memory-agent
```

> ⚠️ **必须 `--build`**：旧镜像里烘焙的 CMD 仍是 `memory_worker.app:combined_app`，不重建会用旧入口导致容器启动即失败；新 `Dockerfile` 已是 `memory_agent.app:combined_app`。
> ⚠️ 只启动 `memory-agent`（compose 会连带起 `redis`/`chroma` 依赖）。`memory-caddy` 不要起——你走 tailscale serve，caddy 占 443 会冲突。

### 11.3 HA 直读数据库（仅当 `HA_DB_ENABLED=true` 时需要）

`ha_db_user` 已改为 `memory_agent_ro`（密码不变，取 `data/config.json` 的 `ha_db_password` 现值）。在 HA MariaDB 新建同名只读账号，否则采集中断：

```sql
CREATE USER IF NOT EXISTS 'memory_agent_ro'@'%' IDENTIFIED BY '<data/config.json 中 ha_db_password 现值>';
GRANT SELECT ON homeassistant.* TO 'memory_agent_ro'@'%';
FLUSH PRIVILEGES;
```

若 `HA_DB_ENABLED=false`（默认），跳过此步。
