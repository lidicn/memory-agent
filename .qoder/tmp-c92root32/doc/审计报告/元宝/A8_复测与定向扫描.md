## 三、定向扫描结果（4 文件，2100+ 行）

按已产出真缺陷的五类模式扫描：

| 文件 | 顺序依赖 | 静默降级 | zip无strict | 裸now | 除法 |
|---|---|---|---|---|---|

| `insights/api.py` (611行) | 1 | 1 | 0 | 0 | 0 |
| `insights/anomaly.py` | 3 | 0 | 0 | 0 | 0 |

### 逐项核查结论

| 位置 | 判定 |
|---|---|
| `api.py:327` `events.sort(key=lambda e: e.ts)` 后再 `[-1]` | ✅ **正确**——显式排序后再取末位 |
| `service.py:801` `for h in range(24)` 构造 `run`，故 `seg[0]<seg[-1]` | ✅ **构造即有序** |
| `anomaly.py:234-236` flapping 计数 | ⚠ 开发者已列为已知 P2，不重复报 |
| **`service.py:68`** `evs[-1].ts` | ⚠ **1 处潜在顺序依赖** |

### `service.py:68` 的性质（低危）

```python
end_ts = tr.end_ts if (tr is not None and hasattr(tr,"end_ts")) else evs[-1].ts
```

未闭合会话的兜底分支。若 `evs` 为 DESC（生产常见），`evs[-1]` 取到**最早**事件，
`end_ts - open_start` 为负 → 会话不追加。

后果是**漏掉一个会话**，而非产生错误数据。触发条件：会话在窗口末尾仍未闭合。
**建议：与 `api.py:327` 一样显式排序，或改用 `max(e.ts for e in evs)`。**
