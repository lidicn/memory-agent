# QA验收规范 v1

> 生效日期：2026-09-20
> 发布方：ADM PM
> 适用范围：所有QA验收工单

---

## 一、QA角色边界

### QA有权做的
- ✅ 复跑开发者交付的判据
- ✅ 登记复跑读数
- ✅ 指出读数与工单描述的不一致
- ✅ 格式退回权：回执缺节直接退回，不必先问PM

### QA无权做的
- ❌ 无设计权：不推荐修法、不做架构判断
- ❌ 不判通过/不通过：只报读数，判定权在PM
- ❌ 不改源码：只读边界内操作
- ❌ 不重启容器/不build/不push

---

## 二、投递格式

### 2.1 投递块
- 路径：`agent-loop/inbox/qa/` 下一个文件一段可整段复制的话
- 首行必须写：`<工单号> §<节号>`
- 示例：`WO-QA-013-MA §三 R-60归属面`

### 2.2 投递清单
- 路径：`agent-loop/投递清单-YYYYMMDDHH【未投】.md`
- 每行一条，不阻塞的一次全发
- 投完改文件名【已投】

---

## 三、回执格式

### 3.1 四节固定模板
```
## 命令        （原样，含容器名/工作目录）
## 输出        （原样尾行，不许整理）
## exit=       （数字，单独一行）
## 结论        （一句话）
```

### 3.2 回执路径
- 落盘：`agent-loop/reports/qa/RPT-<单号>-COMPLETE.md`
- 聊天里只回三行：
  ```
  【To PM】<单号>@待验  <回执路径>
  【To QA】<单号> 待复跑
  【阻塞】无
  ```

### 3.3 格式退回条件
- 缺 `命令/输出/exit=` 任一节 → 直接退回
- 输出被整理过、不是原样 → 退回
- 结论写了"通过/不通过" → 退回（QA不做判定）

## 四、取证三元组（硬要求）

每条现网读数必须自带三元组：
```
UTC时刻 + 镜像sha/容器实像 + homesdk/运行时版本
```

### 正确写法
```bash
docker exec -i <c> sh -c 'python -c "import importlib.metadata as m;print(m.version(\"homesdk\"))"' </dev/null
docker inspect --format '{{.Image}} {{.Created}}' <c>
date -u +%Y-%m-%dT%H:%M:%SZ
```

### 为什么
- 同一容器名在不同时刻是两个不同的世界
- 只写容器名等于没写版本

## 五、取码纪律

### 5.1 取码必须不带管道
错误写法：
```bash
cmd | tail -5; echo $?   # 取到的是 tail 的码，恒为 0
```

正确写法：
```bash
cmd > /tmp/out.txt 2>&1; echo "RC=$?"; tail -5 /tmp/out.txt
```

### 5.2 容器内 /tmp 不是证据仓库
- restart 保留可写层、rm+run/重建清空
- 证据脚本必须落到持久位置（如 `/data`）
- 判据：第三方能不能在容器重建后重跑你的命令

## 六、树的区分

### 6.1 三棵树必须标清
- **作者树**：本地开发目录（如 `E:\NAS\memory-agent`）
- **部署树**：NAS部署目录（如 `/vol1/1000/docker/memory-agent`）
- **容器**：活进程

### 6.2 判据
- 任何读数前缀写成：`作者树 @ master @ <sha>` 或 `部署树 /vol1/... @ main @ <sha>`
- 打回之前先跑「同一 ref 两侧」
- 「读数和作者描述不符」的第一顺位解释是两棵树，不是诚信问题

---

## 七、判据设计原则

### 7.1 判据必须是可复跑的命令
- 不许写「已完成替换」这种动作描述
- 必须写一条能看见命中的 `grep -n`（含期望行号或期望命中数）

### 7.2 判据必须在作者的每个合法选项下都成立
- 做完推荐方案后判据会失败 → 判据作废重写
- 判据失败先查判据，再查作者

### 7.3 完成判据必须是现网绝对路径
- 不许用相对路径
- 必须写清「这条命令在哪台机器的哪个绝对路径上跑」

---

## 八、只读边界

### QA禁做的事
- ❌ 改任何源文件
- ❌ commit / push / 建删 tag
- ❌ restart / recreate / build
- ❌ 设置任何现网环境变量
- ❌ 对活体服务做写入语义的请求

### QA允许做的事
- ✅ 读文件、grep、stat、md5sum
- ✅ docker exec 只读命令
- ✅ 进程内打桩（短命解释器，不落盘）
- ✅ 容器 /tmp 临时文件（跑完删掉）

---

## 九、凭据纪律

- 真实令牌、内网地址、房间名一律未抄录
- 只写键名 / 长度 / 形状
- `/proc/<pid>/environ` 读取仅取键名与非空布尔，不打印任何值

---

## 十、回执里的观察/结论/附注段

### 扫描规则
- 跑 `grep -cE '[A-Za-z0-9_./+-]{20,}'`
- 命中即退回、不读内容

### 豁免条件
- 命中串以 `/` 或盘符开头
- 在文中以路径/文件名形态出现

### 不豁免
- 端点值（`btl_` / `sk-` / `Bearer 长值` / `eyJ` 形态）
- 口令/短语类（`len ≤ 12`）

---

## 附：常见坑

1. **docker exec -i 会吃掉 SSH heredoc 剩余的 stdin** → 每条后面接 `< /dev/null` 或拆成多次 ssh
2. **改代码前先确认改的是「会被 import 的那棵树」** → 一行 `python -c "import <模块> as m; print(m.__file__)"` 定性
3. **活进程不会在运行中重读 .py** → 「现网跑的是 X」必须写成「磁盘上装的是 X」
4. **跨 shell 的中文断言一律用码点字面量** → `chr(0x55EF)` = 「嗯」，不要在命令行里打中文
5. **同一命令、同一口径、同一时刻** → 拿不到单位就不许写「互斥」，只能写「口径未定，待查」
