## 1. 子任务拆分

### T1 · v0.8-2 mem0 式记忆操作（合并管线）— 核心

把写入从「写新 + 判重」升级为 mem0 式四分支（直接抄 mem0，Apache-2.0）：

```
新内容 → 向量近邻召回同 topic_key 旧记忆 →
  ├─ sim < dup_sim               → ADD（新 staging）
  ├─ sim ≥ dup_sim 且兼容/补充   → UPDATE 旧（保留演变链 prev_id，新文本覆盖旧）
  ├─ conflict_sim ≤ sim < dup_sim 且旧是 live → 矛盾 → 新进 pending_review（不自动 INVALIDATE live，安全闸）
  └─ conflict_sim ≤ sim < dup_sim 且旧非 live   → 新更可信 → INVALIDATE 旧 + ADD 新（prev_id=旧）
```

设计要点：
- **演变链**：`agent_memories` 表加 `prev_id TEXT DEFAULT ''`。UPDATE 时把被更新旧记忆 id 写入新记忆
  `prev_id`；INVALIDATE 时把被撤旧记忆 id 写入新记忆 `prev_id`。形成「旧→新」可追溯链。
- **安全闸（沿用 v0.8-1 原则）**：`live` 记忆是已晋升、参与检索的高置信事实，**绝不自动 INVALIDATE**——
  与 live 矛盾的新记忆只进 `pending_review` 等人工裁决，防止 LLM/外部写入幻觉污染权威记忆。
  只有 `staging`/`pending_review` 旧记忆（尚未进 live）才允许被新更可信记忆 INVALIDATE。
- **可信度比较**：矛盾分支默认「新更可信」（写入时间更新、外部已带 source 可信）；无需 LLM 判定的
  重路径。模糊区（dup_sim 与 conflict_sim 之间但主题不明）降级进 pending_review + 可选 LLM 判定（复用
  arena 三层判定的降级模式），本期不做 LLM 判定，统一进 pending_review 待审。
- **统一入口**：新增 `AgentMemoryService.merge_semantic_memory(...)`；`add_semantic_memory` 增加
  `merge: bool = True` 参数，非 dry_run 时默认走 `merge_semantic_memory`（所有 MCP / butler / Web /
  researcher 写入自动受益）；`merge=False` 保留旧「写新 staging」行为（兼容测试）。
- **researcher 接入**：`researcher._dedupe_or_add` 改为调用 `merge_semantic_memory`（保持 dup_sim≥0.92
  → UPDATE 行为，统一管线，消除两套去重逻辑）。
- **chroma 不可用降级**：`merge_semantic_memory` 在 chroma 不可用时退化为「写新 staging」（不合并），
  与现有 `add_semantic_memory` 降级一致，不阻断写入。

改动点：
- `store.py`：`_SCHEMA_SQL` 的 `agent_memories` 加 `prev_id`；`init_schema` 加
  `ALTER TABLE agent_memories ADD COLUMN prev_id`（try/except 兼容旧库）；`add_agent_memory` 加
  `prev_id` 参数；新增 `merge_update_agent_memory(memory_id, text, tags_json, source_refs_json,
  prev_id, ttl_days=None)`（UPDATE 文本/标签/溯源/prev_id/updated_at/mirror_dirty，保留
  created_at/trust/feedback）。
- `agent_memory.py`：新增 `merge_semantic_memory`；`add_semantic_memory` 加 `merge` 参数；
  `conflict_scan` 已返回 neighbors（含 similarity），merge 内复用 chroma query 取 nearest + state。
- `researcher.py`：`_dedupe_or_add` 改用 `merge_semantic_memory`。
- `mcp_server.py` / `tool_schema.py`：`add_semantic_memory` 文档说明「默认合并写入」（契约不变，行为增强）。

验收门：
- 写入语义相同的新记忆 → 第二次返回 `updated`（同 id 文本被刷新），`prev_id` 指向上一版。
- 写入与 live 矛盾的新记忆 → 新进 `pending_review`，live 不动（安全闸生效）。
- 写入与 staging 矛盾的新记忆 → 旧 `staging` 被 `revoked`、新 `staging` 落库且 `prev_id`=旧。
- 写入完全无关内容 → `added`（新 id）。
- 旧库 `agent_memories` 无 `prev_id` 列时 `init_schema` 自动补列，启动不报错。

## 4. 风险

- **live 自动 INVALIDATE**：严禁（安全闸）；模糊矛盾一律 pending_review 待人工。
- **chroma 漂移**：merge 依赖 chroma 近邻；chroma 不可用时降级为纯 ADD，mirror_dirty 由 reconcile 补偿。
- **旧库迁移**：prev_id 用 ALTER 补列；`add_agent_memory` 旧调用方若位置传参需核对（加关键字参数）。
