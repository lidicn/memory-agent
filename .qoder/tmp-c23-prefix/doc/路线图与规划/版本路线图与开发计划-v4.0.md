### vMA-1.2.0 — 场景图与空间记忆（下一版本）

**目标**：从"知道谁在客厅"升级为"知道人在沙发上、电视开着、灯亮着"

**功能交付**：
1. **VLM 场景图输出**：每次 VLM 感知时，除行为标签外，输出结构化场景图（物体 + 关系 + 位置）
   - 输出格式：`{"objects": [{"name": "sofa", "position": "left"}], "relations": [{"subject": "person", "relation": "sitting_on", "object": "sofa"}]}`
   - 存入新表 `scene_graphs`（带时间戳 + 房间 + 人员）
2. **场景图匹配意图**：意图推断增加场景图匹配路径，与行为标签路径并行，取置信度高者
3. **空间语义查询 API**：
   - `GET /api/vision/scene_graph?room=客厅&latest=true` — 获取最新场景图
   - `GET /api/vision/scene_graph?person=Kevin&minutes=30` — 获取某人最近的场景序列
4. **场景历史回放**：支持按时间范围查询场景图序列，用于行为分析

**Bug 修复**：
- 修复 VLM 输出不稳定时场景图解析失败的容错（JSON 解析失败时降级为纯行为标签）

**依赖**：VLM 输出格式需调整（当前只输出行为标签，不输出场景图）
**风险**：中（VLM 输出稳定性需验证）
**预估工作量**：1-2 周

### vMA-1.2.1 — 持续学习与在线适应

**目标**：从"静态规则"升级为"从用户反馈中自动学习新规则"

**功能交付**：
1. **用户反馈接口完善**：
   - `POST /api/feedback` — "这个建议不对"→ 记录负样本（已有基础，需完善）
   - 反馈类型：建议错误 / 时间不对 / 人员认错 / 规则误触发
2. **负样本聚类与规则建议**：
   - 同类负样本积累到阈值（如 3 次）后，自动生成规则建议（需用户确认）
   - 规则建议格式："检测到您纠正了 3 次'Kevin 21:00 后在客厅看电视'的告警，是否添加排除规则？"
3. **规则版本管理**：用户确认的规则可回滚、可禁用
4. **学习日志**：`GET /api/learning/log` — 查看 MA 学到了什么、纠正了什么

**Bug 修复**：
- 修复反馈闭环中 PII 脱敏不完整的边界 case

**依赖**：需要积累用户反馈数据（当前反馈闭环基础设施已就绪）
**风险**：中（规则生成质量需控制，可能生成错误规则）
**预估工作量**：1-2 周

### vMA-1.3.0 — 多模态记忆统一

**目标**：文本记忆 + 人脸特征 + 行为事件 + 视觉快照统一表示

**功能交付**：
1. **统一记忆模型**：所有类型记忆（文本/人脸/行为/场景）统一存储和检索
2. **跨模态检索**：用人脸照片搜索相关文本记忆，或用行为事件搜索相关视觉快照
3. **记忆时间线**：按时间线展示某人的所有记忆事件（文本 + 行为 + 场景）

**Bug 修复**：
- 行为洞察屎山剩余 27 个 FROZEN 方法的最终迁移或归档（见技术债 #1）

**依赖**：较大的架构改动，需要设计统一的数据模型
**风险**：高（架构级改动，需充分测试）
**预估工作量**：2-4 周

## 六、已知难点与未来风险

### 🔴 难点级（已遇到的、难以解决的）

| # | 难点 | 现状 | 影响 |
|---|---|---|---|
| D-1 | **行为洞察屎山迁移** | 3600+ 行代码散落在 insights_legacy.py，多次尝试只迁移了 568 行；代码耦合度高，边界模糊 | 新功能开发困难，容易往屎山堆 |
| D-2 | **446M SQLite 大库性能** | 启动需 5 分钟，查询热路径需索引优化 | 每次部署/restart 都要长时间等待 |
| D-3 | **VLM 输出稳定性** | VLM 补语义输出格式不稳定，JSON 解析经常失败 | 场景图/行为标签可靠性受影响 |
| D-4 | **三棵 git 树同步** | 作者树/裸库/部署树互不可达，部署需 bundle→scp→fetch 手动流程 | 部署流程复杂，容易出错 |
| D-5 | **因果归因假阳性率** | 真实数据中统计检验容易把噪声当显著变化 | 需要调参 + 更多数据验证 |

### 🟡 风险级（未来可能遇到的）

| # | 风险 | 触发条件 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R-1 | **多模态记忆统一导致架构崩溃** | vMA-1.3.0 统一记忆模型设计不当 | 整个记忆层不可用 | 先做 PoC 验证，再逐步迁移 |
| R-2 | **场景图增加 VLM 成本** | 每次感知都输出场景图，token 消耗翻倍 | LLM 费用上升 | 限制场景图采样频率（如 30 秒一次） |
| R-3 | **持续学习生成错误规则** | 负样本聚类错误 → 生成了不该有的规则 | 误告警打扰用户 | 所有自动生成的规则需用户确认才生效 |
| R-4 | **情绪感知准确率低** | 面部表情/语音情感识别不准 | 误导用户 | 先做灰度测试，只用于建议不用于告警 |
| R-5 | **TV 端人脸识别依赖单摄像头** | 罗技 C920 只覆盖电视前区域 | 客厅其他区域无法识别 | 米家摄像头 edge_ai 已作为补充 |
| R-6 | **NAS 资源瓶颈** | 446M SQLite + Chroma + Redis + VLM 同时运行 | 内存/CPU 不足时服务不稳定 | 监控资源使用，必要时升级 NAS |
