## 2. 新增接口

### 2.1 `POST /api/insights/query`（TVPilot / DeskPilot 主通道）

**鉴权**：`Authorization: Bearer <app_token>`（也可用 WebUI 的 JWT）。`app_token` 只放行本路径，越权一律 403。

**模式一：按模板**（语义最稳定，推荐）

```bash
curl -X POST http://<MA>:8086/api/insights/query \
  -H "Authorization: Bearer $APP_TOKEN" -H "Content-Type: application/json" \
  -d '{"template_id":"xbox_daily_usage",
       "start":"2026-09-06T00:00:00","end":"2026-09-07T00:00:00"}'
```

**模式二：按逻辑设备即时查询**（无需预先存模板）

```bash
-d '{"logical_id":"客厅电视","attribute":"source","value":"HDMI 3",
     "metric":"duration","days":2}'
```

`logical_id` 由身份层解析为当前 `entity_id`，因此 HA 重登 / 双集成漂移后依然可用。

**响应**：

```json
{"ok": true,
 "window": {"start": "...", "end": "...", "label": "近2天"},
 "entities": [{"entity_id": "media_player.live_9", "friendly_name": "客厅电视",
               "metric": "duration", "result": {...},
               "resolved": ["media_player.live_9"], "stale": false}],
 "summary_text": "..."}
```

解析不到设备时返回 `stale: true` 与 `result.error`，**不静默返回空**（A3 承诺）。

### 2.2 身份层只读接口（WebUI 用，仅 JWT）

- `GET /api/identity/devices` → `{devices: [...], total}`
- `GET /api/identity/health?state=stale|unknown|active` → `{health: [...], total, state}`

`app_token` **不放行**这两个端点（应用层消费者不该拿到设备清单）。

### 2.3 MCP 语义工具（豆包管家）

- `query_device_usage(logical_device="客厅电视", attribute="source", value="HDMI 3", days=2)`
  与既有 `get_device_usage` 的区别：接受**逻辑设备名**，由身份层解析，漂移免疫，不必先查 `get_entity_catalog`。
- `list_device_health(state="stale")` → A3 失效清单；`referenced=1` 表示仍被模板引用，需优先处理。

## 3. 验证方式

```bash
python -m pytest tests/test_insight_query.py -q   # 12 passed
python -m pytest tests/ -q --continue-on-collection-errors
```

**实测结果**：
- `test_insight_query.py` → **12 passed**
- 全量 → **110 passed，3 failed + 1 error**，与 v0.2 收尾时基线**完全一致**（ACP 循环导入 1 项 + MCP 相关 3 项，本机 mcp SDK 为 1.x 所致，与改动无关）
- 改动文件 lint 0 告警

**部署后观察点**（需 scp 到 NAS `/vol1/1000/docker/memory-agent` 再重建容器）：
1. 环境变量加 `APP_TOKEN=<自定义>`（`docker-compose` 的 `.env`，未配置则通道关闭）；
2. 用 TVPilot 打一次 `POST /api/insights/query`，确认返回 `ok:true`；
3. 用同一令牌打 `GET /api/identity/devices`，应返回 **403**；
4. WebUI 左侧出现「设备身份」页，能看到逻辑设备与失效清单。

## 4. 已知风险与偏差

| 项 | 说明 |
|----|------|
| **MCP 新工具未进工具目录** | `query_device_usage` / `list_device_health` 是 `mcp_server` 内嵌套的手写 `@mcp.tool()`，**未登记到 `tool_schema.TOOL_SPECS`**：`register_simple_tools` 只按显式 `names` 注册，而 `TOOL_NAMES` 会被目录一致性测试用来断言模块级同名函数，嵌套函数不满足。影响仅限内部 `help` / `describe` 目录不列出；MCP 客户端仍能正常发现并调用。v0.6 改为模块级函数（或服务方法 + `generated=True`）后再登记。 |
| **WebUI 路由白名单** | `static/js/store.js` 的 `ROUTES` 必须同步新页面 id，否则会被静默回退到 dashboard。已同步，后续加页面注意。 |
| **`app_token` 无 WebUI 配置项** | 与 `butler_token` 现状一致（设置页也没有 butler 令牌字段），走 `APP_TOKEN` 环境变量。 |
| **只读接口** | 本版本对外**只给「查」不给「控」**，不暴露 HA 写服务，避免应用层越权操作设备。 |

---

## 5. 合并影响

- 新增配置字段 `app_token`，缺省为空（通道关闭），**不影响既有部署**；
- 新增 3 个路由（1 个 POST + 2 个 GET），无破坏性迁移；
- 前端新增一个页面与 3 个 API 方法，纯增量；`store.js` 的 `ROUTES` 与 `index.html` 挂载已同步；
- 未修改任何既有接口的行为，`run_template` 与 v0.2 的解析逻辑保持不变。
