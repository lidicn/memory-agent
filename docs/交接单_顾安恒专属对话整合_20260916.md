## 背景

当前 MA vision_service 每 5 分钟巡检摄像头，调豆包 VLM 分析后结果存 MA DB，但：
1. 每次 VLM 调用都在豆包APP产生一个新的"家庭监控画面人物分析"独立对话，刷屏
2. 管家和 MA 都在调 VLM，有重复
3. 用户无法在一个对话里连续问"起居室现在什么情况"

v2.1 的设计：所有监控分析对话汇聚到顾安恒一个 conversation_id，MA 继续负责巡检，管家负责按需查询和推送。

## MA 需要配合的事项

### 1. vision/analyze API 返回截图URL（必须）

当前 `POST /api/vision/analyze` 返回分析文本，但管家需要把截图也推送到豆包对话。

**要求：**
- 返回值中增加 `snapshot_url` 字段
- 值为 go2rtc 截图的可访问 URL（如 `http://192.168.2.200:1984/api/frame.jpg?src=living_room`）
- 如果取帧失败或无截图，该字段返回 `null`

**当前代码位置：** `src/memory_agent/vision_service.py` 的 `analyze_room()` 方法，返回值在第 743-761 行附近。

### 2. 巡检结果不产生独立豆包对话（必须）

当前 MA 巡检调豆包 VLM 时，每次都创建新对话，导致豆包APP左侧几十个"家庭监控画面人物分析"对话。

**要求：**
- MA 调豆包 VLM 时必须指定 `conversation_id="38440360274498562"`（顾安恒对话）
- 使用 `keep_conversation=True`，不要创建新对话
- 巡检结果只存 MA DB + 写入顾安恒对话，不产生独立对话
- 正常巡检结果不推送文本到对话（只存DB），异常时才推送
- 如果 MA 不直接调豆包 API，而是通过管家中转，则 MA 只需存结果，管家负责推送到顾安恒对话

### 3. 最新分析查询 API（已有，确认即可）

管家需要读 MA 最新巡检结果：
- `GET /api/vision/latest?room=起居室` → 返回最新分析文本 + snapshot_url + 时间戳

如果这个 API 已有，确认返回格式即可。如果没有，需要新增。

### 4. 巡检异常推送（可选，Phase 2）

MA 巡检发现异常（陌生人、门窗异常等）时，通知管家推送：
- 通过 MQTT topic `butler/trigger/gu_anheng_alert` 推送
- payload: `{room, alert_type, message, snapshot_url}`
- 管家收到后通过 doubao2api 推送到顾安恒对话

### ⚠️ 发现并规避的 doubao2api Bug（请管家侧知悉）

**现象**：请求带 `conversation_id` 且**不含 system 消息**、而该会话在 doubao2api 已缓存 system prompt 时，doubao2api 返回 **500**：
`unified_server.py` 续写分支执行 `msgs = [{"role": "system", "content": _cached}] + msgs`（注入一个**裸 dict**），随后 `_extract_prompt` 访问 `msg.role` 抛 `AttributeError: 'dict' object has no attribute 'role'`。

**MA 侧规避**：MA 在带 `conversation_id` 的 VLM 请求中追加 `silent: true`（doubao2api 既有能力，管家推送亦用此模式），走独立分支、不触发该注入；实测 `conv_only=500` / `conv_silent=200`。

**建议管家侧修复**：把注入的 dict 改为 `_Message(role="system", content=_cached)`，从根上消除该 500。
