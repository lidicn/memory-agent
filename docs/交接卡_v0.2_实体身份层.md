# 交接卡：v0.2 实体身份层（Entity Identity & Health）

> 设计依据：`docs/架构设计_MA对外接口与设备身份层.md`
> 路线图位置：v0.2（首个迭代）→ 后续 v0.3 对外查询接口 / v0.4 MQTT / v0.5 记忆统一 / v0.6 治理增强

## 一句话
把「物理设备」与易漂移的 HA `entity_id` 解耦：MA 内部新增逻辑设备身份层，模板与查询只认稳定的逻辑设备名，集成重登 / 双集成冗余导致实体漂移时自动自愈，不再静默失效。

## 1. 改动文件清单

| 文件 | 类型 | 说明 |
|------|------|------|
| `src/memory_agent/identity.py` | **新增** | 身份层全部逻辑：`LogicalDevice` 模型、`IdentityService`（逻辑名→entity_id 解析 + TTL 缓存）、`IdentityReconciler`（对账：A1 重匹配 / A2 自动合并 / A3 失效标记 / 模板自愈）、归一化与相似度工具 |
| `src/memory_agent/store.py` | 修改 | 新增 `logical_devices`、`device_health` 两表（照 `arena_snapshots` 的 `CREATE TABLE IF NOT EXISTS` 范式，`init_schema()` 内自动建，老库无迁移风险）；新增 `list/get/upsert/delete_logical_device` 与 `upsert/get/list_device_health` |

## 2. 行为差异（Behavior Delta）

1. **模板支持逻辑引用**：`EntityQuery.logical_id` 有值时优先按逻辑设备名解析；解析失败**回落**原 `entity_id`。存量模板完全不受影响（灰度过渡）。
2. **`run_template` 输出新增字段**：每实体增加 `resolved`（解析出的候选列表）与 `stale` 标记。
3. **解析失败不再静默**：逻辑名解析不到或全部候选失效时返回 `{"error": "设备已失效或待重匹配…", "stale": True}`，而不是空结果（对应 A3「让用户知情」）。
4. **只有确认在线的实体参与解析**：对账中未出现的实体降级为 `unknown`，长期不可见转 `stale`，二者都不作为故障转移候选——避免拿已下线实体算出旧数据。
5. **启动即对账一次**，随后每 600s 一次（可用 `identity_reconcile_interval_seconds` 覆盖，**未新增配置项**，缺省 600、最小 60）。对账在后台线程执行，失败仅记日志、不阻断启动。
6. **顺带修复**：`BehaviorInsight.from_dict` 此前未恢复 `EntityQuery.metric`（重载后一律回落 `duration`），现已修复。

### 内置模板迁移说明（与原计划的偏差）
原计划「把 `xbox_daily_usage`（写死 `media_player.xiaomi_rmh1_6103_play_control`）硬编码改为逻辑名」。**实际未硬编码**——该设备的 `friendly_name` 未经确认，写死反而可能解析不到。改为运行时自愈：`IdentityReconciler.bind_stale_templates()` 在检测到「模板写死的实体已失效、且身份层已找到新实体」时，自动把该模板改写为逻辑引用并**保留原 `entity_id` 作兜底**。效果等价且更安全（测试 `test_bind_stale_template_to_logical_ref` 覆盖）。

## 3. 验证方式

```bash

python -m pytest tests/test_identity.py -q

# 全量（与基线一致）
python -m pytest tests/ -q --continue-on-collection-errors
```

**实测结果**：
- `tests/test_identity.py` → **16 passed**
- 全量 → **98 passed，3 failed + 1 error**；与改动前基线完全一致（ACP 循环导入 1 项 + MCP 相关 3 项，源于本机 mcp SDK 为 1.x 而项目要求 `mcp>=2.0`，**与本次改动无关，容器内正常**）
- 导入链冒烟：`import memory_agent.runtime / memory_agent.identity` 正常
- lint：改动文件 0 告警

**部署后观察点**（改代码后需 scp 到 NAS `/vol1/1000/docker/memory-agent` 再重建容器才生效）：
- 启动日志出现 `[Identity] 首次对账完成：实体 N，逻辑设备 N，合并 N，重匹配 N，失效 N`
- 之后每 10 分钟一条 `[Identity] 周期对账完成：…`
- HA 短暂不可达时输出 `[Identity] 周期对账跳过: …` 且不改动任何状态

## 4. 已知风险与兜底

| 风险 | 现状 / 兜底 |
|------|-------------|
| **A2 自动合并误并** | 仅在「同 area + 同 domain + 名称相似度 ≥ 0.85」时合并；**跨 area 一律不合并**（`test_cross_room_similar_names_not_merged` 守护）。候选实体保留历史并带 `provenance`，v0.6 做拆分 / 回滚 UI。 |
| **HA 不可达误判全网失效** | 对账拿不到注册表时直接返回 `ha_unreachable` 并**跳过本轮**，不写库（`test_reconcile_ha_unreachable_does_not_break` 守护）。 |
| **身份层未就绪时行为变化** | 无健康记录（尚未对账）时解析一律放行，等同旧行为；`run_template` 无 `identity` 属性时也走旧路径（`test_run_template_compat_without_identity` 守护）。 |
| **v0.2 无可视化** | 身份 / 失效清单目前只能从 SQLite 与日志查看；WebUI「逻辑设备 / 失效清单」页与查询 API 属 **v0.3**。 |
| **内置模板未硬编码逻辑名** | 见上文偏差说明，由运行时自愈覆盖。 |

---

## 5. 合并影响

- **无需改配置**，无破坏性迁移；两张新表由 `init_schema()` 的 `CREATE TABLE IF NOT EXISTS` 自动建立，老库直接升级即可。
- 模板 JSON 新增可选 `logical_id`，老文件缺该字段时 `from_dict` 取空串，**向后兼容**。
- 新增依赖仅标准库（`difflib` / `re`），未引入第三方包。
- `AppRuntime` 多了两个属性与一个常驻任务；`shutdown` 已正确取消，不影响优雅退出。
