## 三、时间有效性设计（任务 1，抄 Graphiti 时间模型 MIT）

### 3.1 数据模型
`agent_memories` 增列：
- `valid_from` / `valid_to`：事实在**真实世界**的有效区间（`valid_to=''` 表示仍有效）。
- `observed_at`：观测时间（事实发生/被观测到的时间）。
- 记录时间复用现有 `created_at`（=recorded_at）。

### 3.2 演变链闭环（与 v0.8 `prev_id` 协同）
mem0 式合并（v0.8）写入时做**时间切片**：
- **INVALIDATE 旧 + ADD 新**（矛盾且新更可信）：
  - 旧记忆 `valid_to = 新记忆 valid_from`（= 新事实生效时刻）；
  - 新记忆 `valid_from = 该时刻`，`prev_id = 旧`。
  → 「上学期 22 点睡（valid_to=8/31）→ 这学期 23 点半（valid_from=9/1）」可回溯。
- **UPDATE 旧**（同 id 刷新，高度相似）：`valid_from` 保持，`updated_at`/`observed_at` 刷新。
- **ADD**：`valid_from = observed_at 或 now`，`valid_to=''`。

### 3.3 检索时效（`retrieve` as_of）
`retrieve(question, ..., as_of=None)`：给定时只返回 `valid_from <= as_of <= valid_to`（或 `valid_to=''`）的记忆——管家可问「上周这条先验成立吗」。

### 3.4 落点
- `store.py`：`agent_memories` 加 3 列（ALTER 迁移）；`add_agent_memory` 加 `valid_from/observed_at` 参数；新增 `close_agent_memory_validity(memory_id, valid_to)`。
- `agent_memory.py`：`merge_semantic_memory` INVALIDATE 分支做时间切片；`retrieve` 加 `as_of`；`list_agent_memories` 映射补 valid 字段。
- `api/agent_memory_routes.py` / MCP 工具：暴露 valid 区间（读写）。

### 3.5 验收门
- 写「A 事实」→ 写与 A 矛盾且新更可信的「B 事实」→ A `valid_to` = B `valid_from`，A `state=revoked`、B `prev_id=A`。
- `retrieve(as_of=晚于切换点)` 不含 A；`as_of=切换点前` 含 A（若当时有效）。
- `list_agent_memories` 返回含 `valid_from/valid_to/observed_at`。
- 旧库自动补列，启动不报错。

## 四、任务 3 设计（MCP 可维护性，已交付 2026-09-16）

### 4.1 响应体上限与超限摘要
- 新增 config `mcp_response_max_bytes`（默认 65536，WebUI「系统设置」可改，已入 `WRITABLE_FIELDS`）。
- 分发层 `_tracked_call_tool` 在 `normalize_tool_result` 之后调 `_apply_response_cap`：
  正文 UTF-8 字节超上限则截断原文到上限、追加「[响应已截断]…请用更窄时间窗/分页/精简接口」摘要；
  保留 `is_error` 标记（动态适配 mcp 1.x/2.x 字段名）。`0` 表示不限制。
- 动机：避免巨响应（如大 `entity_catalog` 667KB）撑爆客户端上下文；截断是服务端保护而非错误。

### 4.2 容器内契约测试
- 新增 `tests/test_mcp_contract.py`（15 项，纯函数/轻协程，无需 runtime 即可跑）：
  - 响应截断：截断发生 / 摘要出现 / 错误标记保留 / 0=不限制；
  - 错误模型：`{"ok":false}` → `isError=True` + 结构化码；
  - 故障注入：按工具与 `*` 短路（真实工具不被调用）/ 清除后双向可控 / 非法码拒绝。
- 容器内：`python -m pytest tests/test_mcp_contract.py`。

### 4.3 故障注入矩阵
- 模块级注册表 `_FAULT_INJECT`（线程安全）；`set_mcp_fault(tool, code)`（tool=`*` 表全部，`code∈ALL_CODES`）、`clear_mcp_faults()`、`list_mcp_faults()`。
- `_tracked_call_tool` 在 scope 检查之后、幂等缓存之前读取注入：命中则返回 `_fault_result`（结构化 `{"ok":false,"error":{"code":...}}` + `isError`），**不执行真实工具**（优先级高于幂等缓存，便于契约验证 / 混沌演练）。
- 依赖不可达的真实降级已由断路器（任务 5）覆盖；本矩阵是「主动触发指定故障」的演练开关，正常业务不依赖。
- 故障→期望行为映射（矩阵）：

| 注入 code | 触发场景 | 客户端应做的契约处理 |
|---|---|---|
| `NOT_FOUND` | 资源不存在（成员/模板/记忆/技能） | 提示资源不存在，引导创建/纠正 id |
| `INVALID_PARAM` | 参数缺失/非法 | 回显缺参，重新收集后重试 |
| `UPSTREAM_UNAVAILABLE` | HA/LLM/chroma/功能未启用不可达 | 进入降级（纯规则合成/重试/提示依赖未就绪） |
| `DENIED` | 令牌无 write / 写回未授权 | 提示权限不足，引导开权限或手动操作 |
| `RATE_LIMITED` | 限流 | 退避后重试 |
| `INTERNAL` | 未分类内部错误 | 上报/重试，必要时人工排查 |
