## 0 · 结论速览（先看这）

1. **Frigate 是什么**：开源、完全本地的 NVR（网络录像机），核心是"实时本地 AI 目标检测"，专为 Home Assistant 设计。用 OpenCV + TensorFlow，检测 human/pet/vehicle 并做区域(zone)、追踪(tracking)、录制。
2. **它正好补 MA 的缺口**：书房（ipc009）、小黄人（ipc019e）**完全没有盒侧 AI**，目前只能靠最贵的"go2rtc 取帧→VLM"。上 Frigate 后，这两路摄像头获得**免费、实时、本地的 person/face/pet 检测**，把"Gate 前移"到本地、零云成本。
3. **Double Take 不用了**：Frigate v0.16+ 已**内置人脸识别**（FaceNet-small 跑 CPU / ArcFace-large 跑 GPU-NPU），官方文档明确"用 Double Take 会与内置识别冲突"。新项目直接用内置，省一套组件。
4. **算力**：3 路以内用 **Coral USB（~10ms/帧，单实例）** 最稳；若 NAS 是 Intel（多半带 iGPU），用 **OpenVINO-GPU 检测器（~30ms、可并发）零额外硬件**更香。CPU 检测器官方不推荐。
5. **接入 MA 的路径**：Frigate → MQTT（`frigate/events` 等主题）→ HA（已有 MQTT 集成）→ MA 把 HA 事件写进统一 `perception_events` 总线。复用现有 go2rtc 的 xiaomi 流，不增加摄像头连接数。
6. **客厅怎么办**：客厅（chuangmi.051a01）盒侧 AI 已免费实时（人脸 known/unknown、人形、宠物、哭声、手势…），**建议保留盒侧 AI 不动**，Frigate 只接管书房+小黄人。若想要跨摄像头统一追踪/区域，也可把客厅也纳入 Frigate（算力盈余时）。

## 1 · Frigate 能力清单（实测/官方）

### 1.1 目标检测（物体检测器）
- **可检测类别**：COCO 全集（91 类），家庭相关主要有 `person / bicycle / car / motorcycle / dog / cat / …`；`face` 不在基础 COCO，需 Frigate+ 模型或支持 face 的自定义模型才加入跟踪。
- **默认只跟踪 `person`**，其余需在配置 `objects.track` 中显式声明（如 `car / dog / cat`）。
- **检测器硬件**（不能混用多种做物体检测）：
  | 类型 | 设备 | 推理速度 | 适用 |
  |---|---|---|---|
  | `edgetpu` | Coral USB / PCIe / M.2 | ~10ms（**单模型实例**，须足够快） | 低功耗、小机型首选 |
  | `openvino` | Intel CPU/GPU/**iGPU/NPU** | ~30ms（**可并发多实例**） | Intel NAS 零额外硬件 |
  | `onnx`/`tensorrt` | Nvidia/AMD GPU、Jetson | ~30ms 并发 | 有独显/开发板 |
  | `cpu` | 纯 CPU | 官方**不推荐** | 仅兜底 |
  - 推荐模型分辨率 **320×320**（Frigate 会裁剪运动区放大再检，对小物体更友好）。
- **运动检测先行**：先靠帧差发现活动区域，再把该区域送检测器推理 → 省算力。

### 1.2 人脸识别（内置，v0.16+）
- **两种本地模型**：
  - `small`（FaceNet 嵌入，CPU 可跑，效率高精度较低）
  - `large`（**ArcFace** 嵌入，精度高，需 GPU/NPU）
  - 先轻量关键点对齐人脸，再嵌入；**多帧决策**：人在画面期间对多帧识别，最终 `sub_label`（人名）按**人脸面积加权**（越近越大权重越高），非单帧。
- **工作前提**：必须先检测到 `person`，再在其框内扫人脸；用 Frigate+ 模型时把 `face` 加入 `objects.track` 即可与物体检测并行。
- **训练/注册**：UI 的 Face Library「Add Face」上传 → Train 标签分配给人 → 建议每人人脸 **5–10 张起步、理想 20–50 张**（正脸+稍偏角，避免模糊/红外/批量过拟合）。
- **输出**：识别到的人名作为 `sub_label` 挂到 `person` 对象上，进 UI/过滤器/通知/MQTT。

### 1.3 MQTT 事件（HA / MA 消费入口）
- 默认主题前缀 `frigate`，事件核心主题 **`frigate/events`**（非 `frigate/+/events`）。
- `frigate/events` 载荷（节选）：
  ```json
  {
    "type": "update",            // new | update | end
    "before": { ... },
    "after": {
      "id": "1607123955-mxklsc",
      "camera": "study_room",
      "label": "person",         // person / car / dog ...
      "sub_label": ["lidicn", 0.79],   // 人脸识别结果 [名字, 分数]
      "top_score": 0.958,
      "score": 0.878,
      "box": [432,496,544,854],  // 检测框
      "current_zones": ["desk_area"], // 进入的区域
      "entered_zones": ["desk_area"],
      "stationary": false,
      "attributes": {"face": 0.86}
    }
  }
  ```
- 人脸专项：`frigate/tracked_object_update`（type=`face`，含 `name`/`score`/`camera`/`timestamp`）。
- 聚合审查：`frigate/reviews`（含 `data.objects`/`data.sub_labels`/`data.zones`，适合报警汇总）。
- 计数：`frigate/<camera>/<object>`（纯数字计数）、`.../active`、`frigate/<zone>/<object>`。

### 1.4 Home Assistant 集成实体（HA 侧）
需先装 MQTT 集成 + 配置 Frigate MQTT。暴露：
- `camera.*`：实时流（依赖 RTSP 8554）。
- `binary_sensor.*_motion`：每摄像头/区域/物体的运动传感器（低延迟、可能误报，严格场景用 MQTT 事件）。
- `sensor.*`：各区域/摄像头物体计数 + Frigate 性能状态。
- `image.*`：每摄像头最新检测图（通知可附）。
- `switch.*`：检测/录制/快照开关（自动化里动态开关）。
- **Notification API**：`/api/frigate/notifications/<event-id>/{thumbnail,snapshot,clip}.*`，免公网暴露富媒体通知。

| 摄像头 | 现状（盒侧 AI） | Frigate 价值 | 建议 |
|---|---|---|---|
| **客厅** chuangmi.051a01（AI 增强版） | 人脸 known/unknown、人形、宠物、婴儿哭声+醒来、手势、昼夜、看护、收藏区域、**85 HA 实体** | 重复（盒侧已免费实时）。Frigate 额外给跨摄像头追踪/区域，但算力冗余 | **保留盒侧 AI**，Frigate 不重复接管；如需统一 zone 可后续纳入 |

## 3 · NAS 部署方案（Docker，复用现有 go2rtc）

### 3.1 流接入：复用现有 go2rtc，不增加摄像头连接
MA 已有一个独立 go2rtc 容器（`/vol1/1000/docker/go2rtc/go2rtc.yaml`，定义了 `cam_客厅`/`cam_书房`/`cam_小黄人` 三个 xiaomi 流）。两种复用方式：

- **方式 A（推荐）**：Frigate 用**自己的内置 go2rtc**，但在 `go2rtc.streams` 里把源指向**现有 go2rtc 的 RTSP restream**：
  ```yaml
  go2rtc:
    streams:
      cam_书房:
        - rtsp://192.168.2.200:8554/cam_书房      # 复用现有 go2rtc 已建立的连接
      cam_小黄人:
        - rtsp://192.168.2.200:8554/cam_小黄人
  ```
  这样摄像头只被现有 go2rtc 连一次，Frigate 从 restream 拉，连接数不翻倍。
- **方式 B**：Frigate 内置 go2rtc 直接写 xiaomi 源（与现有 go2rtc.yaml 重复一份 xiaomi:// 配置），简单但摄像头被连两次。

### 3.2 检测器（算力）
- **优先 OpenVINO-iGPU**：若 NAS 是 Intel（多数家用 NAS/迷你主机是），`type: openvino, device: GPU` 用核显，**零额外硬件**、~30ms 可并发，2–3 路轻松。
- **否则 Coral USB**：插一个 Google Coral USB（`--device=/dev/bus/usb` 映射），`type: edgetpu, device: usb`，~10ms。单实例够 2–3 路。
- **不推荐纯 CPU**（2 路实时会卡）。

### 3.3 配置骨架（docker-compose 片段）
```yaml
frigate:
  container_name: frigate
  restart: unless-stopped
  ports: ["8971:8971", "8554:8554"]   # UI / RTSP
  volumes:
    - /vol1/1000/docker/frigate/config:/config
    - /vol1/1000/docker/frigate/media:/media    # 事件 clips/snapshots
  devices:
    - /dev/dri:/dev/dri          # OpenVINO iGPU（Intel）
    # - /dev/bus/usb:/dev/bus/usb  # 或 Coral USB
  environment:
    FRIGATE_RTSP_PASSWORD: "<REDACTED-弱口令 len=11>"
```
```yaml
# config/config.yml
mqtt:
  host: 192.168.2.200        # HA 的 MQTT broker
  topic_prefix: frigate
detectors:
  ov: { type: openvino, device: GPU }   # 或 coral: { type: edgetpu, device: usb }
cameras:
  cam_书房:
    ffmpeg: { inputs: [ { path: rtsp://192.168.2.200:8554/cam_书房, roles: [detect, record] } ] }
    detect: { width: 1280, height: 720, fps: 5 }
    objects: { track: [person, face, dog, cat] }   # face 需 Frigate+ 模型
    zones:
      desk_area: { coordinates: ... }
  cam_小黄人:
    ffmpeg: { inputs: [ { path: rtsp://192.168.2.200:8554/cam_小黄人, roles: [detect, record] } ] }
    detect: { width: 1280, height: 720, fps: 5 }
    objects: { track: [person, face] }
face_recognition:
  enabled: true
  model_size: small          # small=FaceNet/CPU, large=ArcFace/GPU
```
> 注：NAS 部署属后续执行项，本文仅给出方案，未改动任何运行容器。

## 4 · 事件对齐到 MA `perception_events`（核心集成）

MA 路线图 Phase 0 设计了统一感知总线 `perception_events(source, kind, payload, ts)`。Frigate 事件是 `source=edge_ai` 的第二类来源（客厅盒侧 AI 是第一类）。

### 4.1 映射表
| Frigate 信号 | `source` | `kind` | `payload` 关键字段 |
|---|---|---|---|
| `frigate/events` label=person, type=new | `edge_ai` | `person_seen` | camera, score, box, zones |
| `frigate/events` sub_label=[name,score]（人脸） | `edge_ai` | `face_known` / `face_unknown` | name, score, camera |
| `frigate/events` label=dog/cat | `edge_ai` | `pet_seen` | camera, label |
| `frigate/events` entered_zones | `edge_ai` | `zone_enter` | camera, zone |
| `frigate/events` type=end | `edge_ai` | `person_left` | camera, duration |

### 4.2 落地方式（二选一）
- **方式一（推荐，复用 HA）**：Frigate→HA MQTT 集成→HA 生成实体/事件→MA 用现有 `ha_client` 增量监听 HA 状态/事件变更，写 `perception_events`。好处：MA 代码最小改动、与客厅盒侧 AI 走同一消费路径；坏处：多经 HA 一层。
- **方式二（直连 MQTT）**：MA 直接订阅 `frigate/events` 与 `frigate/tracked_object_update`，写 `perception_events`。好处：最低延迟、不依赖 HA 中间层；坏处：MA 需加一个 MQTT 订阅客户端（当前 MA 没有 MQTT 订阅能力，只有 HA REST/websocket + go2rtc 取帧）。

> 建议：**Phase 0 先接客厅盒侧 AI（走 HA，零新依赖）**；Frigate 上线时若已确认 HA-MQTT 链路可用，方式一最省力；若追求低延迟或 HA 不稳定，再补方式二的 MQTT 直连。

## 5 · Double Take 还要不要？—— 不要

- **现状**：Frigate v0.16+ 已内置人脸识别（FaceNet-small / ArcFace-large），训练走 UI Face Library。
- **官方结论**：文档明确"使用另一个人脸识别服务（如 Double Take）**会干扰 Frigate 内置识别**"——二者 `sub_label` 机制冲突。
- **结论**：新部署**直接用 Frigate 内置人脸识别**，不再引入 Double Take / DeepStack / CompreFace。Double Take 仅在"坚持用 COCO 模型 + 外挂识别"的老架构里才有意义，对 MA 是多余复杂度。
- 客厅盒侧 AI 的人脸（known/unknown）与 Frigate 的人脸是**两套独立信号源**，可在 MA 的 Identity 层做融合（路线图 Phase 1 Identity 三路融合：客厅盒侧 + TV ArcFace + Frigate），互为校验。

## 6 · 成本 / 复杂度 / 风险 vs 现状

| 维度 | 现状（仅 VLM 取帧） | 上 Frigate（书房+小黄人） |
|---|---|---|
| 书房/小黄人 语义 | 无（仅 motion 触发后取帧→VLM，贵、慢、非实时） | 本地 person/face/pet 实时、免费 |
| 云/VLM 成本 | 高（每次取帧调 VLM） | 大幅下降（Gate 前移到本地） |
| 新组件 | 无 | Frigate 容器 +（可选）Coral |
| 复杂度 | 低 | 中（新增检测器调优、zone 标定、MQTT 对接） |
| 算力 | 无新增 | Coral USB 或 Intel iGPU |
| 风险 | — | 米家 xiaomi 流 4–13s 关键帧间隔（go2rtc 已知），检测帧率受限；H.265 可能需转码 |

**米家流注意点**（来自 MA 现有 go2rtc 经验）：米家摄像头关键帧间隔 4~13s，Frigate 实时检测受此限制（检测 fps 实际约 1/间隔）。对"人来了/宠物出现"这类低频语义足够，但对高速运动捕捉弱。这是盒侧 AI 与 Frigate 的共有瓶颈，非 Frigate 独有。

## 7 · 决策建议（给路线图 Phase 0 的选型）

1. **先接客厅盒侧 AI（零成本、立竿见影）**：Phase 0.1 订阅客厅 `event.*` 盒侧 AI → `perception_events`。这步不动 Frigate 也能立刻多一批免费实时信号。
2. **Frigate 作为 Phase 0 的"补齐书房/小黄人"手段**：在 NAS 起 Frigate，复用现有 go2rtc 流，检测器用 OpenVINO-iGPU（若有 Intel）或 Coral USB，仅接管书房+小黄人，做 person/face/pet + zone。
3. **弃用 Double Take**，Frigate 内置人脸识别；客厅盒侧人脸与 Frigate 人脸在 MA Identity 层融合。
4. **事件经 HA MQTT → MA `perception_events`**（方式一），必要时再补 MQTT 直连（方式二）。
5. **不急于给客厅也上 Frigate**：盒侧 AI 已覆盖，避免算力与事件重复；待 Frigate 在书房/小黄人跑稳、且想要跨摄像头统一 zone/追踪时再评估。
