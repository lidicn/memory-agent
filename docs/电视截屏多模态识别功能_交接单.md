## 一、功能需求

在 memory-agent 中增加**按需调用**的电视截屏多模态识别功能，支持：

1. **获取电视当前屏幕截图**（通过 HA xiaomi_miot 集成）
2. **获取当前电视打开的 App 信息**（同 API 返回）
3. **多模态识别截图内容**（识别正在观看的电影/电视/界面）
4. **结合 TV 端状态广播**（MQTT `tv/livingroom/state`）做更精准的上下文理解

**重要**：此功能为**按需调用**，不需要定时轮询。用户或豆包管家在需要时触发（如用户问"电视上在放什么？"、豆包管家主动观察客厅情况等）。

### 2.1 截图获取方式（已验证可行）

#### 方案 A：直接访问电视（推荐，速度快，不经过 HA 代理）

```python
import requests

HA_TOKEN = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJjNmQxNmQwNDk0YjA0MGQ2OWM0NWM5ZGQ2ZDIzMTM1MSIsImlhdCI6MTc4ODM2MjE0MiwiZXhwIjoyMTAzNzIyMTQyfQ.oYkOSzeHEtyVcQGfpcq-pY8ZScfuzrAcQvuXXqaCWLY"
HA_URL = "http://192.168.2.200:8123"
ENTITY = "media_player.xiaomi_rmh1_6103_play_control"

def get_tv_screenshot():
    """获取电视截图和当前应用信息"""
    # 1. 获取实体状态（包含最新的截图 URL）
    resp = requests.get(
        f"{HA_URL}/api/states/{ENTITY}",
        headers={"Authorization": f"Bearer {HA_TOKEN}"},
        timeout=10
    )
    attrs = resp.json()["attributes"]
    
    # 2. 直接从电视获取截图（capture 属性是电视的直接 URL）
    capture_url = attrs.get("capture")
    if not capture_url:
        return None, None
    
    img_resp = requests.get(capture_url, timeout=15)
    screenshot_bytes = img_resp.content  # JPEG 图片数据
    
    # 3. 获取当前应用信息
    app_current = attrs.get("app_current", "")  # 如 "桌面 - com.mitv.tvhome"
    app_page = attrs.get("app_page", "")
    
    return screenshot_bytes, {
        "app_current": app_current,
        "app_page": app_page,
        "capture_token": attrs.get("capture_token", ""),
        "entity_state": resp.json().get("state", "")  # playing/paused/stop
    }
```

### 2.2 重要注意事项

#### Token 过期机制

电视的截图 URL 包含 `timestamp` 和 `opaque`（签名），**会过期**。因此：

- ❌ **不要缓存截图 URL**
- ✅ **每次需要截图时，先调用 `/api/states/` 获取最新的 `capture` URL**
- ✅ HA 每约 30 秒更新一次实体状态，所以每次获取的 URL 都是新鲜的

#### 截图 URL 格式示例

```
http://192.168.2.238:6095/request?action=getResource&name=screenCapture
  &timestamp=1788442177909
  &opaque=aed2137e7392a929ad9a526a7f59e950371826c2
```

- 直接访问电视 TCP 6095 端口（MITV API）
- **不需要 HA 认证**，但 URL 本身有签名时效

### 2.4 结合 TV 端状态广播（MQTT）

TV Cam 项目已实现 **TV 状态广播**，每 5 秒通过 MQTT 发布电视状态：

**MQTT Topic**：`tv/livingroom/state`（retained）
**MQTT Broker**：`tcp://192.168.2.200:1883`
**认证**：用户名/密码（NAS mosquitto）

**状态数据结构**：
```json
{
  "screen_on": true,
  "foreground_app": "com.fongmi.android.tv",
  "foreground_app_name": "飞牛TV",
  "media_playing": true,
  "media_paused": false,
  "media_package": "com.fongmi.android.tv",
  "media_title": "无间道",
  "volume": 25,
  "volume_max": 100,
  "volume_muted": false,
  "tv_cam_running": true,
  "ts": 1788442177909
}
```

**使用建议**：
- memory-agent 可以订阅此 MQTT topic，缓存最新的电视状态
- 做多模态识别时，把 TV 状态作为上下文传入，提高识别准确度
- 例如：TV 状态显示 `foreground_app_name=飞牛TV, media_title=无间道`，结合截图可以确认"用户正在用飞牛TV看《无间道》"

## 四、应用场景

### 4.1 用户主动查询
- 用户："电视上在放什么？"
- memory-agent：获取截图 → 多模态识别 → 回答"正在用飞牛TV看《无间道》，播放到第 35 分钟"

### 4.2 豆包管家主动对话
- 人体传感器检测到用户在客厅电竞沙发上
- 豆包管家主动获取电视截图，识别到用户在看《无间道》
- 豆包管家："你在看《无间道》啊，这部电影的经典台词是..."

### 4.3 结合记忆
- memory-agent 记录用户的观影习惯（常看什么类型、什么时间看电视）
- 可以推荐类似影片，或在用户看电影时自动调暗灯光

### 4.4 异常检测
- 识别到电视长时间停留在桌面/设置界面，可能用户睡着了
- 可以提醒用户或自动关闭电视
