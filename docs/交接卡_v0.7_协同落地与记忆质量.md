## 二、部署方式（含关键坑）

```bash

# 2) 纯源码改动：docker restart 即可

# 3) 跑冒烟（等待窗口已放宽到 180s）
docker exec -i memory-agent python3 - < /vol1/1000/docker/memory-agent/scripts/smoke_e2e.py
```

### 三个已踩过的坑（务必遵守）

1. **禁止使用 `deploy_nas.sh`**：它会 `git checkout -f origin/main` 覆盖未 push 的改动。
2. **改 `.env` 后必须 `docker compose up -d`（重建容器）**，不能用 `docker restart`——
   restart 复用旧环境变量，本次 `MA_MQTT_ENABLED=1` 就是 restart 无效、
   改 `up -d --build` 后才生效的。
3. **新增 pip 依赖必须 `docker compose up -d --build`**（重建镜像）。
   MA 启动约需 **2 分钟**（首轮 HA 采集 + 身份对账），**实测有时超过 150s**，
   uvicorn 在 startup 完成前**不监听 8000**，冒烟/验证等待窗口必须 **>180s**。
4. **轮换凭据时，光改 `.env` 不生效**：`get_config()` 只在配置值为空时才用环境变量
   覆盖，而 MA 运行期间会把 config 持久化到 `data/config.json`——凭据一旦被写进去，
   之后改 `.env` 会被忽略。轮换密码/令牌时必须**先清空 `config.json` 中对应字段**
   （使其回落到 env），否则会出现「broker 已换新密码、MA 仍在用旧密码」的静默失败。
   本次已验证：清空后重启，`password_matches_env = True`，连接与推送立即恢复。

### 本次实际执行的部署动作

- `.env` 追加 `MA_MQTT_ENABLED=1`、`BACKUP_ENABLED=1`
- 重建镜像并 recreate 容器：`docker compose up -d --build memory-agent`
- 回滚备份：改动前已把 NAS 上的 `src` 备份到 `/tmp/ma_src_bak`

## 四、过程中修复的缺陷（非计划内，但属本版本收益）

1. **`collect_lag_seconds` 为负**：容器时钟为 UTC，而 `last_event_ts` 是本地时间。
   改用 `now_local(tz_offset_hours)` 对齐后，实测由 `-28180` 变为 `1073`（约 18 分钟）。
2. **MQTT 推送失败后永不重试**：`last_key` 在 `publish_presence()` 返回 False 时也被更新，
   导致首次推送失败后再也不会重推。改为仅成功才更新。
3. **同日重复备份失败**：`VACUUM INTO` 不允许目标文件已存在。改为先删除当日旧快照。
4. **MQTT 静默失败**：`connect()` 异步、无 `on_connect`，连接被拒时 `publish()` 仍返回 True，
   消息被丢弃且无任何日志。已补 `on_connect` 打印 + 未连接时判失败。
5. **Dockerfile 漏装 `paho-mqtt`**：`pyproject.toml` 声明了但镜像没装，
   MQTT 能力实际不可用（本次构建已修复）。
6. **`config.py` 的 `env_map` 只映射 `tv_mqtt_user`、漏了 `tv_mqtt_pass`**（v0.4 遗留）：
   配了用户名却永远读不到密码，broker 一律「未授权」——这是 P0-1 的**真实根因**。
   已补 `"tv_mqtt_pass": "TV_MQTT_PASS"`。
7. **`health.mqtt.connected` 判断不可靠**：原用「客户端对象是否存在」，
   而 paho 被 broker 拒绝后仍保留对象并持续重连，导致长期显示 `connected=true`
   却一条消息都发不出去（本次排查被它误导）。已改为 `is_connected()`。

## 五、遗留问题与风险

### 1. MQTT 在场推送（P0-1）—— ✅ 已闭环

- **现象**：`ma/presence` 无消息；订阅端与发布端均为 `on_connect rc = 5`（未授权）。
- **根因（两层）**：
  1. 表层：`tv_mqtt_user` / `tv_mqtt_pass` 为空，而 broker 配置 `allow_anonymous false` 要求认证。
  2. **真实根因**：`config.py` 的 `env_map` **只映射了 `tv_mqtt_user`、漏了 `tv_mqtt_pass`**——
     即便把密码写进 `.env`，MA 读到的密码长度始终为 0。已补 `"tv_mqtt_pass": "TV_MQTT_PASS"`。
- **处理**：新增 broker 专用账号 `memory-agent`（**未改动**现有 `lidicn` / `butler`，
  避免打断 TV 与管家链路），随机强密码；写入 `.env`；
  `docker compose up -d --no-deps memory-agent` 重建（`--no-deps` 避免连带重启 chroma/redis）。
- **broker 侧**：`docker kill -s HUP mosquitto` 重载（**未重启**：`Up 6 days` 未变），
  现有 MQTT 客户端无感知。
- **验收**：`ma/presence` 收到 MA 真实快照 `{"members": [], "total": 0, "ts": "..."}`
  （`members` 为空是因当前确实无在场数据，与「person 字段通常为空」的已知缺口一致）；
  `health.mqtt.connected = true`（且已改为真实 `is_connected()`）。
- **凭据存放**：账号 `memory-agent`，密码见 NAS `/vol1/1000/docker/memory-agent/.env`，
  请同步存入密码管理器。取回命令（**不要**让明文进入聊天/工单）：
  ```
  ssh lidicn@192.168.2.200 "grep '^TV_MQTT_PASS=' /vol1/1000/docker/memory-agent/.env"
  ```
- **已轮换一次**：初版密码曾出现在对话记录中，已作废并换新。
  新密码在 NAS 上生成、直接写入 broker 与 `.env`，**明文未经过聊天**。
  轮换后已实测：`password_matches_env = True`、`[MQTT] 已连接 broker`、
  `ma/presence` 收到 MA 推送的真实快照 `{"members": [], "total": 0, "ts": "2026-09-10T13:40:42"}`。
- **轮换步骤备忘**：① 远端生成新密码 → ② `mosquitto_passwd -b` 更新（`-u 1883` 保属主）
  → ③ `docker kill -s HUP mosquitto` 重载 → ④ 更新 `.env`
  → ⑤ **清空 `data/config.json` 的 `tv_mqtt_pass`** → ⑥ 重启 MA → ⑦ 订阅验证。

> **踩坑记录**：验证时用探针手动发了一条 retain 到 `ma/presence`，而 MA 的
> 「内容变化才推」逻辑认为内容未变、不再重推，导致该测试残留**长期占据 retain**，
> 险些误导管家 P0-4 联调（会拿到假的「连通性探针在书房」）。已用
> `mosquitto_pub -r -n` 清除。
> **教训：绝不在真实业务 topic 上发 retain 测试消息，测试请用独立 topic。**

### 2. chroma 集合文档数为 0

- `chroma_status` 返回 `{'connected': True, 'host': 'chroma:8000', 'documents': 0}`。
- 本次 `up -d` 时 `memory-chroma` 也被 recreate（数据在 `chroma_data` 卷，应保留）。
- 需在观察期确认是长期状态还是重建导致；若确需重建，可跑 `reindex_embeddings.py`。

### 3. embedding 端点待定

- 尚未提供 URL + key，当前为默认 MiniLM，中文语义检索质量未提升。
- 接入步骤：`.env` 加 `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` / `EMBEDDING_API_KEY`
  → `docker compose up -d` →（因维度变化需）`scripts/reindex_embeddings.py` → 再重启一次。

### 4. 备份文件日期用容器 UTC

- 备份文件名为 `ma-20260909.db` 而本地日期为 09-10。若需与本地日对齐，
  应改用 `now_local(tz_offset_hours)` 生成日期戳（当前为 `datetime.now()`）。
