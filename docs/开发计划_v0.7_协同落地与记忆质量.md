## P0-1 MQTT 推送启用 + 管家联调（0.5 天）

### 背景
管家回复单点名：当前 `ma/presence` 无消息，其定位引擎 P0-4（最强信号源，权重 1.0）无法端到端验证。代码侧 v0.4 已实现、v0.6 已加固周期重连，**只差配置启用**。

### 步骤
1. 确认 broker：复用 TV 截屏链路现有 broker（`tv_mqtt_host/port` 同源），避免新基础设施
2. NAS `.env` 追加：
   ```
   MA_MQTT_ENABLED=1
   MA_MQTT_HOST=<broker 地址，与 tv_mqtt_host 一致>
   MA_MQTT_PORT=1883
   MA_MQTT_TOPIC_PREFIX=ma
   MA_MQTT_PRESENCE_INTERVAL=60
   ```
   （无引号包裹；`.env` 注入后 `docker restart memory-agent`）
3. 自测：`mosquitto_sub -t 'ma/presence'`（或容器内 python 订阅）确认 retain 消息；人在镜头前走动后 ≤3 个周期内收到变化推送
4. 通知管家联调其 P0-4（`MaPresenceSource` 订阅 + 房间名映射）

### 验收
- [ ] `ma/presence` retain 可订阅，载荷含 name/room/via/confidence/last_seen
- [ ] 成员位置变化后推送内容变化（不是每 60s 空转重发）
- [ ] 断开 broker 30s 再恢复：v0.6 周期重连生效，无需重启 MA
- [ ] 管家侧确认：定位引擎收到 `arcface_recognized` 信号，lidicn 置信度 ≥0.9
- [ ] TV 截屏 MQTT 链路无回归（`ma/` 前缀隔离验证）

## P0-2 butler 专属 app_token + 记忆写入联调（0.5 天）

### 步骤
1. WebUI 设置页「应用令牌」创建：`name=butler-core, source=butler`，令牌明文经安全渠道交付管家
2. 管家按其 P0-5 改造写入链路（`Authorization: Bearer <butler-core 令牌>` 调 `POST /api/agent/memories`）
3. 联调验收后，如管家需要可另建 `tvpilot` / `deskpilot` 令牌（各自 source）

### 验收
- [ ] 管家写入 → MA 落库 `source=butler, state=staging`
- [ ] body 谎报 `source=ma` → 仍落 butler（v0.6 令牌派生，已在容器实测过）
- [ ] 管家检索按 source 过滤可用
- [ ] 吊销令牌后管家写入立即 401

## P0-3 冒烟测试固化进部署流程（1 天）

### 交付
- `scripts/smoke_e2e.py`（容器内执行，复用本轮手搓 e2e 的流程）：
  1. 等待 8000 就绪（带重试，避免重启窗口误报）
  2. `/proc/1/environ` 取 JWT_SECRET 造 JWT（仅容器内可用）
  3. 建临时 app_token → 写记忆断言来源派生 → 列合并审计 → 吊销断言 401 → 清理测试数据
  4. 任一步失败 `exit 1` 并打印步骤名
- `deploy_nas.sh` 末尾追加：`docker exec -i memory-agent python3 - < scripts/smoke_e2e.py`，非零退出即部署失败回显

### 验收
- [ ] 连续两次真实部署，冒烟自动全绿
- [ ] 人为注入坏代码（如路由名打错）时冒烟能红

## P1-1 向量模型升级（2 天）

### 背景
三个 chroma collection（`behavior_history`/`agent_memory`/`arena_titles`）均未指定 embedding_function，用默认 MiniLM-L6（英文向、384 维）。中文家庭记忆语义检索质量受限——这是 v0.8 记忆研究员/混合检索的地基。

### 设计
- `config.py` 新增（对齐 `llm_backends` 范式）：
  ```
  embedding_base_url: str = ""      # OpenAI 兼容 /v1/embeddings
  embedding_model: str = ""         # 如 bge-m3 / Qwen3-Embedding / doubao-embedding
  embedding_api_key: str = ""       # env: EMBEDDING_API_KEY
  ```
- `history.py`：三个 collection 的 `get_or_create_collection` / `add` / `query` 注入统一 embedding 函数；`embedding_base_url` 为空时保持现状（默认 MiniLM），**零配置不破坏现有部署**
- 新增 `scripts/reindex_embeddings.py`：从 SQLite 权威数据全量重刷三个 collection（先写 `*_v2` 新 collection，刷完原子改名切换，检索零空窗）
- `runtime.health()` 增加 embedding 后端 ping 状态

### 验收
- [ ] 未配置 embedding 时行为与现在完全一致（回归）
- [ ] 配置后：20 条人工中文对照查询，top-5 命中率显著优于旧镜像（记录对比数据进交接卡）
- [ ] 重刷期间检索不空窗；失败可回退（旧 collection 保留至确认后删）
- [ ] `health()` 显示 embedding 后端与维度

## 风险

| 风险 | 应对 |
|---|---|
| MQTT broker 争用/认证缺失 | 与 TV 链路同源配置；联调前先 `mosquitto_sub` 自测 |
| embedding 服务商延迟/配额 | 重刷脚本带速率限制与断点续刷；保留旧 collection 可回退 |
| 联调节奏与管家不同步 | P0-1/P0-2 各自验收标准已写入双方文档，先自测后约联调窗口 |
| 冒烟脚本误报（重启窗口） | 已内置端口就绪等待；失败输出步骤名便于定位 |
