### 4. 发现的问题

按严重程度排序：

1. 🔴 **teach_signal 的 dry_run=true 被忽略，真实写入生产数据**
   - 调用：`teach_signal(dry_run=true, name=MCP测试规则, room=书房, activity=working, entity_id=binary_sensor.0x00158d0001a2520d_motion)`
   - 结果：返回 `已写入信号硬排除（无歧义硬排）`，exclusion_id=`5e13db3466e79f2b`
   - 验证：`list_signal_rules` 显示 hard=1，created_by=mcp，revoked=false
   - 加重：**74 个工具中无任何撤销信号排除的接口**，测试残留无法清理
   - 已上报：`bug_6baaadccbd`（major）

2. 🔴 **create_member 空 name 未拦截，且无成员删除接口**
   - 调用：`create_member(name="")` → `ok=true`，真实创建 id=`a4dd7578a1c44d0ab52790d4c04f1cc9`
   - 验证：`list_members` total 3→4，空名成员持久化
   - 加重：工具集中无 `delete_member`，残留无法清理
   - 已上报：`bug_6ae9e7d8fc`（major）

3. 🔴 **assign_member_room 对不存在的 member_id 返回成功**
   - 调用：`assign_member_room(member_id="nonexistent_member_123", rooms=["书房"])` → `ok:true 关联房间已更新`
   - 实际为静默 no-op（未产生幽灵成员），但虚假成功会误导调用方

4. 🟠 **list_candidate_rules 的 status=all 返回 0，与 staging=23 矛盾**
   - `status="staging"` → count=23；`status="all"` → count=0，all 参数疑似未生效

5. 🟠 **list_members 的 tags 未按预期裁剪**

   - 实际：含 id、member_id、tag、emoji、confidence、evidence_json、source、confirmed_at、created_at、evidence 全字段（响应 ~10KB+）

6. 🟠 **读类工具被 DENIED 为写工具**
