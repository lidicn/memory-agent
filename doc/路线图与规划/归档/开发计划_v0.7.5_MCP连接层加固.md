## 为什么做（一句话）

当前 **任何一枚 `mcp_` 令牌 = 53 个工具的完全读写权，且运行完全无审计**。
v0.8 要引入「记忆研究员」（后台自动写入）与「mem0 式 UPDATE/INVALIDATE」（改写存量记忆），
在放开自动化写之前必须先把「谁能动、动过什么」管起来——
与 v0.7 提前做「备份/DR 先于存量改写」是同一个道理。

## P0-1 工具级 scope 授权（1 天）

### 背景
中间件（`mcp_auth.py:56`）只做 `store.verify(token)` 判空，**没有任何权限维度**。
高风险工具与只读工具完全等价暴露：`trigger_collection`（副作用）、
`delete_analysis_template`（删除）、`rollback_agent_memory`（整段回滚，破坏性）、
`analyze_camera`（取摄像头帧，隐私）、`save_skill`（写文件）。

### 步骤
1. **建立工具 → scope 映射表**（放 `tool_schema.py`，与单一 schema 真源同处，
   避免「文档写一套、实现另一套」）。四档：
   - `read`（默认）：`help` / `get_*` / `list_*` / `search_events` / `query_events` /
     `ask_memory` / `retrieve_agent_memories` / `export_insight` / `get_skill` 等
   - `write`：`add_semantic_memory` / `promote_memory` / `revoke_memory` /
     `feedback_memory` / `sweep_promote_candidates` / `create_member` /
     `assign_member_*` / `confirm_member_tag` / `define_activity` / `teach_signal` /
     `save_analysis_template` / `save_skill`
   - `admin`：`trigger_collection` / `trigger_incremental_collection` /
     `export_history` / `delete_analysis_template` / `rollback_agent_memory`
   - `vision`：`analyze_camera`
2. **令牌记录增 `scopes` 字段**（`mcp_tokens.py:105` 的 `record`），
   默认 `["read"]`；WebUI 签发页可勾选。
3. **存量令牌迁移**：为「保证现有 Agent 不断连」（沿用 `migrate_legacy` 的既有原则），
   已有令牌一律补全 `read/write/admin/vision`；**新建令牌默认只读**。
4. **中间件解析 JSON-RPC**：在 `MCPTokenMiddleware` 中读取 body 取出
   `method` 与 `params.name`（`tools/call`），比对令牌 scopes 后决定放行/拒绝。
   - ⚠️ 关键实现点：ASGI 的 `receive()` 只能消费一次，
     必须**包装 receive 收集 body 并重放**，否则下游拿到空 body。
   - 防御：body > 1 MB 不解析，直接放行（避免大 payload 内存风险）。
5. 拒绝时返回**明确错误码**（不是 200 包裹体）：
   `{"jsonrpc":"2.0","error":{"code":-32003,"message":"DENIED: 令牌缺少 write 权限"}}`

### 验收
- [ ] 只读令牌调 `add_semantic_memory` → 明确 `DENIED`，**不是** `ok:false`
- [ ] 只读令牌调 `get_behavior_insights` → 正常
- [ ] `admin` 工具（如 `trigger_collection`）在只读/只写令牌下均被拒
- [ ] 存量令牌行为**完全不变**（全 scope）
- [ ] body 未被消费破坏：正常工具调用参数完整到达（重点回归带复杂参数的分页工具）

## P0-2 操作审计（0.75 天）

### 背景
现有日志只有 `_log.info("MCP dispatch %s %s -> %s", method, path, transport)`
（`app.py:425`）——**不记工具名、耗时、成败、哪个令牌**。53 个工具完全黑盒运行，
出问题无法回答「谁在何时动了什么」，也不满足「关键动作形成可追溯审计链」。

### 步骤
1. 新增 `mcp_audit.py`：ASGI 中间件，在 #1 已有的 body 解析基础上记录
   `{ts, token_name, tool, duration_ms, ok, error_code}`，并包装 `send` 捕获状态码。
2. 落独立 SQLite 表 `mcp_audit`（不并入 events，避免污染行为数据）；
   **异步 `to_thread` 写入，失败仅记日志、绝不阻塞主链路**。
3. 保留期默认 30 天，随 v0.7 已就位的每日备份任务顺带清理。
4. 暴露只读查询入口（WebUI「MCP 接入」页一张审计表 + 一个只读 MCP 工具），
   按 token / tool / 时间筛选。

### 验收
- [ ] 任意一次工具调用都能查到「谁 / 何时 / 哪个工具 / 耗时 / 成败」
- [ ] 审计写入失败不影响工具正常返回
- [ ] 审计表不进入事件库与洞察统计（`stats()` 口径不变）

## P0-3 kind 身份隔离（0.5 天）

### 背景
MCP / ACP / debug 三类令牌共用 `config.agent_tokens` 一张表，
而 `verify()` 只按 hash 比对返回 name，**不校验 `kind`**。
`app.py` 注释虽写明「mcp_ 令牌仅用于 /mcp」，但 `/mcp` 侧并未强制——
`acp_`、`dbg_` 令牌存在访问 `/mcp` 的可能（需实测确认）。

### 步骤
1. `MCPTokenStore.verify(token, expected_kind=None)`：命中后比对
   `record["kind"]`（缺省视为 `mcp`），不符返回 `None`。
2. `MCPTokenMiddleware` 传 `expected_kind="mcp"`；
   `ACPTokenMiddleware` 传 `expected_kind="acp"`。
3. 先写测试确认现状（是否真的越权），再修——**用测试固化，避免口头结论**。

### 验收
- [ ] `acp_` 令牌访问 `/mcp` → 401
- [ ] `dbg_` 令牌访问 `/mcp` → 401
- [ ] `mcp_` 令牌访问 `/acp` → 401
- [ ] 三类令牌各自链路无回归（管家 / autoflow / 调试接口）

## P0-4 Origin / Host 纵深防御（0.5 天）

### 背景
`mcp_server.py:1712` 显式关闭了 DNS rebinding 保护
（`TransportSecuritySettings(enable_dns_rebinding_protection=False)`），
理由是「端点已有 Bearer Token 鉴权」。这在局域网场景可接受，
但等于**把所有防护压在一个 Bearer 上**：一旦令牌泄露或将来出现免鉴权工具即全线失守。

### 步骤
1. 在 `MCPTokenMiddleware` 增加 Origin 白名单校验。
2. **兼容策略**：非浏览器客户端（DeepSeek++、管家等）通常不携带 Origin 头，
   因此**仅在 Origin 存在时校验**，缺省放行——避免误伤现有客户端。
3. 白名单可配置（默认允许局域网与已配置域名），支持关闭。

### 验收
- [ ] 携带非白名单 Origin 的请求被拒
- [ ] 不带 Origin 的现有 MCP 客户端**全部无回归**（重点：管家、DeepSeek++）
- [ ] SSE 与 Streamable HTTP 两种传输均正常

## 明确不做（本版）

- 不改任何工具签名与返回契约（错误模型、Resources、Prompts 属 v0.9）
- 不做 OAuth / 授权服务器（家庭局域网 + Caddy TLS + Bearer 足够）
- 不做限流 / 配额 / 响应体上限（v0.9 P2）
- 不拆分 MCP Server、不上网关（53 个工具已偏多，应「分层暴露」而非拆分）

## 风险

| 风险 | 应对 |
|---|---|
| 读 body 破坏下游请求 | 包装 receive 重放；>1MB 不解析直接放行；重点回归复杂参数工具 |
| scope 收敛误伤现有 Agent | 存量令牌默认全 scope，新建默认只读；全量回归 |
| 审计写入放大压力 | 独立表 + 异步 `to_thread` + 保留 30 天，失败不阻塞 |
| 测试与运行环境版本漂移 | 契约测试固定跑在**容器内**（本机 mcp SDK 为 1.x，与项目 `mcp>=2.0` 不符） |
| Origin 校验误伤客户端 | 仅在 Origin 存在时校验，缺省放行 |

## 验收门（不满足不进 v0.8）

1. 只读令牌调用写工具返回明确 `DENIED`（非 200 包裹体）。
2. `acp_` / `dbg_` 令牌访问 `/mcp` 被拒。
3. 任一工具调用可在审计中查到「谁 / 何时 / 哪个工具 / 耗时 / 成败」。
4. 53 个工具全量回归：读工具在只读令牌下行为不变，SSE 与 Streamable HTTP 双通道正常。
