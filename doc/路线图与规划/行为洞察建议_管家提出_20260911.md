# memory-agent 行为洞察能力建议

> 提出方：豆包管家
> 日期：2026-09-11
> 目的：列举 MA 能完成、对用户体验有提升的行为洞察能力

---

## 背景

豆包管家正在建设记忆系统，从对话中自动学习用户习惯。但管家只有对话数据，没有视觉数据和行为数据。

memory-agent（MA）已经有摄像头、人脸识别、在场感知、作息分析等能力，但这些能力没有充分利用起来。

**原则**：MA 做物理世界的记忆（视觉、在场、作息、行为），管家做语言世界的记忆（对话、偏好、家庭成员）。两边数据融合，形成完整用户画像。

---

## MA 已有的能力（管家可以直接调）

| 接口 | 用途 | 管家用来干嘛 |
|------|------|-------------|
| `GET /api/vision/presence` | 在场感知 | 知道谁在哪个房间 |
| `GET /api/members` | 成员列表 | 知道家庭成员有谁 |
| `GET /api/insights/member-schedule` | 作息基线 | 知道什么时候起床、睡觉 |
| `PATCH /api/members/{id}` | 更新成员信息 | 同步管家提取的家庭成员信息 |

---

## 建议 MA 新增的行为洞察能力

### 1. 习惯学习（Habits）

**能力描述**：MA 自动学习用户在不同时间、不同场景下的行为模式。

**数据来源**：
- 摄像头视觉事件（谁在哪、什么时候在）
- 设备状态变化（灯什么时候开、空调什么时候开）
- 用户位置变化（从哪个房间移动到哪个房间）

**输出格式**：
```json
{
  "member": "lidicn",
  "habits": [
    {
      "time_range": "07:00-08:00",
      "room": "客厅",
      "activity": "看电视",
      "frequency": "每天",
      "confidence": 0.9
    },
    {
      "time_range": "22:00-23:00",
      "room": "书房",
      "activity": "用电脑",
      "frequency": "每天",
      "confidence": 0.85
    }
  ]
}
```

**管家怎么用**：
- 早上 7:20，看到 lidicn 在客厅 → 主动说"早啊老板，今天还是看 CCTV1 吗？"
- 晚上 10:00，看到 lidicn 在书房 → 主动说"老板，该睡觉了，明天还要早起呢"
- 用户说"打开电视" → 自动调到 CCTV1（因为知道用户习惯看 CCTV1）

**为什么 MA 做比管家做好**：
- MA 有摄像头数据，能真实看到用户在做什么
- 管家只有对话数据，只能推断用户"说过"什么

---

### 2. 异常行为检测（Anomaly Detection）

**能力描述**：MA 检测用户行为偏离正常模式，主动提醒。

**数据来源**：
- 正常作息基线（member_schedule）
- 实时行为数据（presence、设备状态）

**输出格式**：
```json
{
  "member": "lidicn",
  "anomaly": {
    "type": "late_sleep",
    "description": "你平时 23:00 睡觉，现在已经 01:00 了还在书房",
    "severity": "warning",
    "confidence": 0.9
  }
}
```

**管家怎么用**：
- 凌晨 1:00，看到 lidicn 还在书房 → 主动说"老板，都一点了，该睡觉了"
- 早上 7:30，看到 lidicn 还在主卧室 → 主动说"老板，该起床了，今天要赶高铁呢"
- 晚上 8:00，看到家里没人 → 主动提醒"老板，你还没回家吗？"

**为什么 MA 做比管家做好**：
- MA 有实时在场数据，能知道用户在哪
- MA 有作息基线，能知道用户正常什么时候活动

---

### 3. 房间使用模式（Room Usage）

**能力描述**：MA 统计每个房间什么时候被谁使用。

**数据来源**：
- 摄像头视觉事件（谁在哪个房间）
- 设备状态变化（灯什么时候开）

**输出格式**：
```json
{
  "rooms": {
    "客厅": {
      "usage_pattern": "早上7-9点看电视，晚上8-10点吃饭",
      "members": ["lidicn", "kevin", "emily"],
      "peak_time": "19:00-21:00"
    },
    "书房": {
      "usage_pattern": "晚上9-12点用电脑",
      "members": ["lidicn"],
      "peak_time": "21:00-23:00"
    }
  }
}
```

**管家怎么用**：
- 用户说"我在书房" → 自动打开书房灯和空调
- 凯文进客厅 → 自动把电视切到他喜欢的频道
- 爱美丽进客厅 → 自动打开音乐

**为什么 MA 做比管家做好**：
- MA 有摄像头数据，能真实知道谁在哪个房间
- 管家只有对话数据，只能推断用户"说在"哪个房间

---

### 4. 家庭成员互动模式（Family Interaction）

**能力描述**：MA 分析家庭成员之间的互动模式。

**数据来源**：
- 摄像头视觉事件（谁和谁同时在哪个房间）
- 设备状态变化（谁用了什么设备）

**输出格式**：
```json
{
  "interaction_patterns": [
    {
      "members": ["lidicn", "kevin"],
      "room": "客厅",
      "time_range": "周末下午",
      "activity": "一起玩游戏",
      "frequency": "每周六日",
      "confidence": 0.8
    }
  ]
}
```

**管家怎么用**：
- 周六下午，看到 lidicn 和 Kevin 都在客厅 → 主动说"要不要一起玩 Xbox？"
- 周日早上，看到爱美丽在客厅 → 主动说"要不要放点音乐？"

**为什么 MA 做比管家做好**：
- MA 有摄像头数据，能真实看到谁和谁在一起
- 管家只有对话数据，不知道家庭成员什么时候在一起

---

### 5. 设备使用习惯（Device Usage）

**能力描述**：MA 分析用户什么时候用什么设备。

**数据来源**：
- 设备状态变化（灯什么时候开、空调什么时候开）
- 用户位置（谁在设备旁边）

**输出格式**：
```json
{
  "member": "lidicn",
  "device_habits": [
    {
      "device": "显示器挂灯",
      "time_range": "20:00-24:00",
      "room": "书房",
      "frequency": "每天",
      "confidence": 0.9
    },
    {
      "device": "客厅空调",
      "time_range": "22:00-07:00",
      "room": "主卧室",
      "frequency": "每天",
      "confidence": 0.85
    }
  ]
}
```

**管家怎么用**：
- 晚上 8:00，看到 lidicn 进书房 → 自动打开显示器挂灯
- 晚上 10:00，看到 lidicn 进主卧室 → 自动打开主卧室空调
- 用户说"打开灯" → 自动打开他习惯开的灯

**为什么 MA 做比管家做好**：
- MA 有设备状态数据，能知道设备什么时候开
- MA 有用户位置数据，能知道谁在用设备

---

### 6. 活动模式识别（Activity Recognition）

**能力描述**：MA 通过摄像头视觉，识别用户在做什么活动。

**数据来源**：
- 摄像头视觉事件（用户姿态、动作）
- 设备状态变化（电视开着、电脑开着）

**输出格式**：
```json
{
  "member": "lidicn",
  "current_activity": {
    "type": "watching_tv",
    "confidence": 0.9,
    "room": "客厅",
    "since": "2026-09-11T07:15:00"
  }
}
```

**管家怎么用**：
- 看到 lidicn 在看电视 → 不打扰他
- 看到 lidicn 在用电脑 → 不打扰他
- 看到 lidicn 在发呆 → 主动问"要不要帮你做点什么？"

**为什么 MA 做比管家做好**：
- MA 有摄像头视觉，能识别用户在做什么
- 管家只有对话数据，不知道用户在做什么

## 优先级排序

| 优先级 | 能力 | 对用户体验提升 | 开发难度 |
|--------|------|---------------|---------|
| P0 | 习惯学习 | 高（主动服务） | 中 |
| P0 | 异常行为检测 | 高（主动提醒） | 低 |
| P1 | 房间使用模式 | 中（自动场景） | 中 |
| P1 | 设备使用习惯 | 中（自动控制） | 中 |
| P2 | 家庭成员互动模式 | 低（锦上添花） | 高 |
| P2 | 活动模式识别 | 低（锦上添花） | 高 |

---

## 建议分阶段实施

### 第一阶段（1-2 周）
1. **习惯学习**：MA 自动学习用户在不同时间的行为模式
2. **异常行为检测**：MA 检测用户行为偏离正常模式

### 第二阶段（2-4 周）
3. **房间使用模式**：MA 统计每个房间什么时候被谁使用
4. **设备使用习惯**：MA 分析用户什么时候用什么设备

### 第三阶段（4-8 周）
5. **家庭成员互动模式**：MA 分析家庭成员之间的互动
6. **活动模式识别**：MA 通过摄像头视觉识别用户在做什么

## 与管家的协作方式

### 数据流向

```
MA（物理世界）                    管家（语言世界）
    │                                  │
    ├─ 习惯学习结果 ──────────────────► │
    ├─ 异常行为检测结果 ──────────────► │
    ├─ 房间使用模式 ──────────────────► │
    ├─ 设备使用习惯 ──────────────────► │
    │                                  │
    └─────────────── 数据融合层 ───────┘
                           │
                           ↓
                    完整用户画像
                           │
                           ↓
                    记忆审核（WebUI）
                           │
                           ↓
                    记忆投喂（豆包长期记忆）
```

### API 接口建议

**MA → 管家（推送）**：
- `POST /api/insights/habits` — 推送习惯学习结果
- `POST /api/insights/anomaly` — 推送异常行为检测结果

**管家 → MA（拉取）**：
- `GET /api/insights/habits?member=lidicn` — 拉取习惯学习结果
- `GET /api/insights/rooms` — 拉取房间使用模式
- `GET /api/insights/devices` — 拉取设备使用习惯

---

## 总结

**核心原则**：
- MA 做物理世界的记忆（视觉、在场、作息、行为）
- 管家做语言世界的记忆（对话、偏好、家庭成员）
- 两边数据融合，形成完整用户画像

**建议优先做**：
1. 习惯学习 —— 让管家知道用户习惯，主动服务
2. 异常行为检测 —— 让管家知道用户异常，主动提醒

这两个能力对用户体验提升最大，开发难度也相对较低。
