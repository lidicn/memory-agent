## 1. ①(c) 运行面负控（容器内写 `/app/src` 必须失败）

**要证什么**：容器对宿主源码目录**运行面无写权**（不是只看 compose 文本里的 `:ro`）。
**窗口（命令级，全部由链主在出资人授权下执行；MA 席位不在场、不碰容器）**：
1. **正控（同批必出）**：`docker exec memory-agent python -c "import os; print(os.getuid())"` ⇒ 期望非 root；`docker exec memory-agent test -r /app/.env; echo $?` ⇒ 期望 `0`（只判可读，⛔ `cat`，凭据值本体⛔ 出境）。
2. **负控（这一格的判据）**：`docker exec memory-agent sh -c 'echo probe > /app/src/.write_probe_window; echo rc=$?'` ⇒ 期望**非 0**，且 stderr 指名 `Read-only file system`（或 `Permission denied`）。
3. **反控（判负控是否有效）**：`docker exec memory-agent sh -c 'echo probe > /tmp/.write_probe_window && echo ok'` ⇒ 期望 `ok`（容器文件系统**可写**）。⛔ 若 `/tmp` 也写不进去，说明 exec 面本身坏了，第 2 步的 rc≠0 **不作数**。
4. 若第 2 步意外成功：**立刻** `docker exec memory-agent rm -f /app/src/.write_probe_window`，记录 rc，本条**判 FAIL**（不是"写成功也算过"）。
**时长**：~5 分钟。
**谁在场**：出资人授权那一次 `docker exec`；链主执行并把四条 rc＋stderr 原文写进证据件。
**前置**：容器在跑；①(a)（compose `./src:/app/src:ro` 与 `./.env:/app/.env:ro` 同口径）与 ①(b)（AST 锁 `tests/test_sidecar_update_contract.py` 腿 1）盘上现绿——本席 11-15 现读为绿，点击前再复跑一次即可（`python -m pytest tests/test_sidecar_update_contract.py -q`）。
**失败长什么样**：
- 写成功 ⇒ **FAIL**，红因写「挂载不是 `:ro`」或「NAS 部署目录 compose 与 E 盘不同步」；
- rc≠0 但 stderr 是 `No such file or directory` ⇒ **无效读数**（路径不对，不是只读），⛔ 记 PASS；
- `/tmp` 正控失败 ⇒ 整批**无效**，重开窗；
- 只跑负控不跑正控/反控 ⇒ 同批缺控，⛔ 作为结论。

## 2. ② 一次真实点击链·四件同批

**要证什么**：WebUI 点"更新并重启"后，**整条 sidecar 链真的跑通**，而不是 `result.ok=True` 单证（结构事实：`scripts/host_update.sh:112` `write_result True ""` **早于** `:117` `docker restart memory-agent`，且重启 rc 从不回读 ⇒ `ok=True` 可能早于重启、也可能重启失败仍为 True）。

**四件（缺一件即不成立，⛔ 分次补）**：
1. 预览件 `GET /api/system/update/check` ⇒ `has_update=true`；
2. marker **曾被创建又被摘**：点击后短时间内 `pending=true` 且 `.update_request.json` 存在；收尾时 `pending=false` 且该文件**不存在**（由容器写、宿主脚本摘）；
3. `GET /api/system/update/status` ⇒ `result.ok=true` ∧ `result.error` 为空串；
4. **重启后四件同批（2026-11-16 02 窗口后定形，旧「版本号等式」已作废）**：
   (a) `StartedAt` 变化（重启真发生）；(b) `result.to` == 宿主 `HEAD` == **点击后 fetch 的** `origin/main`（⛔ 用点前快照值）；(c) 容器内能读到本笔更新的**特征行**（示例：`docker exec memory-agent grep -n "tv/livingroom/status" /app/src/memory_agent/config.py`）；(d) 下一次 precheck 后 `preview.local_commit == result.to`。
   ⚠️ **旧口径已作废**（原字：`result.to.startswith(current_version.split("+")[-1])`）：`__init__.py:33` 在 import 时读 preview、`system_routes.py:23` 把版本号烤死，preview 又 5 分钟一轮 ⇒ **第一次重启上 `current_version` 必然是更新前的 sha**，旧等式恒假。版本类读数必须在更新完成 **≥1 个预检周期（5 分钟）之后**取，否则会把「取样太早」判成假绿/假红。

**窗口（顺序即判据，⛔ 调换）**：
0. **点击前**（出资人/链主同批记录，未点之前的基线）：
   - `docker inspect memory-agent --format '{{.State.StartedAt}} {{.State.Status}}'`（重启前实例起点）；
   - 宿主仓 `git -C /vol1/1000/docker/memory-agent status --porcelain` ⇒ 期望**空**（`host_update.sh` 会 `git reset --hard`，脏改动会被冲掉；有脏改动 ⛔ 开点）；
   - 宿主仓 `git rev-parse HEAD` 与 `git rev-parse origin/main`（作 #3 的"点击前"点刻）；
   - WebUI 侧读 `current_version`（页面自读；⛔ 把 admin JWT 交给任何人）。
1. 等预检 cron 至少跑完一轮（`*/5`），确认 `.update_available.json` 的 `checked_at` 是新的、`has_update=true`；
2. **出资人亲手点**"更新并重启"，并输入当前版本号二次确认（这是 DCD Q4=B 的闸，⛔ 代点）；
3. 点击后 ≤2 min 内连读 `status`：先看到 `pending=true`（marker 在），再看到 `pending=false`＋`result` 写入；
4. 容器重启后（`StartedAt` 变化、`/health` 回到 ready）再读一次 `current_version` 与 `status`，做第 4 件等式；
5. 同刻转 #3。

**时长**：~20 分钟（其中等预检 ≤5 min、重启等待 ≤2 min）。
**谁在场**：**出资人**（唯一能点 WebUI 更新并做版本号确认的人）＋**链主**（宿主只读取数、写证据件、出判语）；MA 席位不在场。
**前置（缺一不可）**：
1. **有一笔真实改动使 NAS 落后**：11-15 23:5x 现读已满足（`has_update=true`，本地 `3be924c9` vs 远端 `b3c0064`），**无需再 push**。窗口当天若已被一次自然更新吃掉变 `false` ⇒ 等一笔自然积压，或由出资人决定接受哪一笔真实改动；**⛔ 为凑 `has_update` 造提交，⛔ 手造 marker／伪造 preview**（那是假绿）；
2. 预检 cron 在跑且 preview 未陈化超一个周期；
3. 宿主仓干净（见步骤 0）；
4. `data/` 可写（`tar` 备份与 `prune_update_backups.py` 都要落盘）；

**失败长什么样（逐件点名，⛔ 合并成一句"失败"）**：
- 件 1 不成立（`has_update=false`／preview 陈化）⇒ **窗口作废**，不是 FAIL；补一笔 push 重开；
- 件 2 只见 marker 创建、收尾仍 `pending=true` ⇒ 停在宿主脚本，FAIL（附 `data/update.log` 尾部）；
- 件 3 `ok=false` ⇒ 按 `error` 原文记录：`git fetch 失败`／`git reset 失败`／`语法检查失败，已自动回滚` 三选一，并**同时**核对代码是否已回滚到点击前 HEAD；
- 件 3 `ok=true` 但 `StartedAt` 未变 ⇒ **FAIL（假绿）**，红因写「`write_result` 早于 `docker restart`」这条在册结构事实；
- 件 3 `ok=true` 且重启发生，但件 4 不成立 ⇒ FAIL，按件点名：`StartedAt` 未变（假绿）／三枚不等（宿主不同步）／容器内读不到特征行（容器看到的是旧树）／下轮 precheck 后 `preview.local_commit` 仍不等 `result.to`；⚠️ ⛔ 再因「`current_version` 的 sha 对不上」判红——旧口径已作废，见件 4；
- 重启后容器 `started` 但 `/health` 不 ready ⇒ 记 `PARTIAL`＋容器日志尾部，⛔ 判 PASS。

**要证什么**：`result.to` == 宿主仓 `HEAD` == `origin/main` tip，三枚**同一时刻**取；席位侧 `git rev-list --count origin/main..HEAD` == 0（MA 自读，本席每回合现读）。

**失败长什么样**：
