# 交接卡：v0.4 MQTT 实时推送

> 设计依据：`docs/架构设计_MA对外接口与设备身份层.md`
> 前置版本：v0.2 实体身份层、v0.3 对外查询接口

## 一句话
让 TVPilot / DeskPilot 从「轮询」升级为「被推送」：MA 把**成员在场快照**与**设备健康变化**发布到 MQTT，TV / PC 订阅后渲染实时卡片；推送为旁路能力，任何失败都不影响主流程。

## 2. 主题与载荷

| 主题 | 触发时机 | retain | 载荷 |
|------|----------|--------|------|
| `ma/presence` | 周期（默认 60s），**内容变化才发** | ✅ | `{"members":[{name, member_id, room, via, confidence, last_seen, trigger}], "total":N, "ts":"..."}` |
| `ma/device-health` | 对账发现状态变化（active ↔ unknown ↔ stale） | ❌ | `{"entity_id","stable_id","from","to","ts"}` |

订阅验证：

```bash
mosquitto_sub -h 192.168.2.200 -p 1883 -t 'ma/#' -v
```

---

## 3. 启用方式

在 NAS 的 `.env`（`/vol1/1000/docker/memory-agent/.env`）加：

```env
MA_MQTT_ENABLED=1                 # 开关，未开则 publish() 直接空转
# broker 复用既有 TV Cam 配置
TV_MQTT_HOST=192.168.2.200
TV_MQTT_PORT=1883
TV_MQTT_USER=
TV_MQTT_PASS=
```

- `MA_MQTT_TOPIC_PREFIX`（默认 `ma`）、`MA_MQTT_PRESENCE_INTERVAL`（默认 60s，最小 15s）**仅在配置为默认值时由环境变量生效**（沿用项目既有约定：环境变量不覆盖已保存的配置）；要改非默认值请改配置文件。
- 依赖 `paho-mqtt` 已加入 `pyproject.toml`，**部署时必须重建镜像**才生效。

## 4. 验证方式

```bash
python -m pytest tests/test_mqtt_bridge.py -q   # 11 passed
python -m pytest tests/ -q --continue-on-collection-errors
```

**实测结果**：
- `test_mqtt_bridge.py` → **11 passed**
- 全量 → **121 passed，3 failed + 1 error**，与 v0.3 收尾时基线**完全一致**（ACP 循环导入 1 项 + MCP 相关 3 项，本机 mcp SDK 为 1.x 所致，与改动无关）
- 改动文件 lint 0 告警

**部署后观察点**（scp 到 NAS 并 `docker compose up -d --build`）：
1. 启动日志出现 `[MQTT] 实时推送已启用 → <host>:<port> 主题前缀 ma`；
2. `mosquitto_sub -t 'ma/#' -v` 能看到 `ma/presence`（有人被识别后）；
3. 手动让某个设备离线并等对账，应收到 `ma/device-health`，且**只收到一次**（状态不变不重复发）。

## 5. 已知风险与偏差

| 项 | 说明 |
|----|------|
| **`ma/device-usage` 未实现（偏离原设计）** | 原路线图列了设备用量推送。但 MA 的数据是**批量轮询采集**（最小间隔 15 分钟），无法支撑「已玩 45 分钟」这类分钟级实时卡片——硬做只会给出滞后且不准的数字。设备用量继续走 **v0.3 的 HTTP 按需查询**（拉模型才是它的正确形态）。若 TV 端确实要秒级状态，应直接订阅 HA 自身的状态流，而不是经 MA 中转。 |
| **生态联调未完成** | TVPilot / DeskPilot 是外部项目（不在本工作区），需部署后由它们订阅主题做端到端联调。本版本只保证 MA 侧正确发布。 |
| **推送降级不告警** | broker 不可达时只打印一次 `[MQTT] 客户端不可用` 并停止重试，避免每轮刷日志；代价是 broker 恢复后需**重启 MA**才重新推送（v0.6 可加周期性重连）。 |
| **在场推送有延迟** | 在场是周期快照（默认 60s）而非事件驱动，最坏延迟 ≈ 一个周期。这样设计是为了不侵入视觉识别的热路径；若后续要更低延迟，可在视觉事件写入处加钩子。 |

## 6. 合并影响

- 新增 1 个模块与 3 个配置字段，**默认关闭**（`ma_mqtt_enabled=False`），不开即完全空转，对既有部署零影响。
- `identity.reconcile()` 的返回新增 `health_changes` 字段（纯增量，旧调用方读取 `stale` 的行为不变）。
- `_mark_stale()` 的返回值由 `int` 改为 `list[dict]`——**内部方法**，无外部调用方（已全量测试验证）。
- 新增第三方依赖 `paho-mqtt`，**部署需重建镜像**。
