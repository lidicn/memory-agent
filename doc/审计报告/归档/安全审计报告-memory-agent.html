F9低无 CSRF 防护，但默认不落 Cookie → 仅在客户端自行把令牌存 Cookie 时成立

核对 全仓检索 set_cookie / SameSite / HttpOnly = 0 处（后端不写 Cookie，令牌经响应体下发、前端以 Authorization 头回传）；但 app.py:431-440 的鉴权链保留了 cooky 分支（读 token= Cookie）。

结论 默认不构成 CSRF 面；若部署方（或某客户端）把 JWT 存进 Cookie 且未设 SameSite，则所有写端点（含 /api/config/reveal、/api/config、/api/users/delete）都可能被跨站请求触发。条件性，非当前默认配置下的漏洞。

修复 若坚持 Cookie 方案：加 SameSite=Lax/Strict + HttpOnly + CSRF token；否则删除该 Cookie 分支以免日后被误用。

F10低MCP 不可用时把导入错误文案回显给调用方（信息面已收窄）
