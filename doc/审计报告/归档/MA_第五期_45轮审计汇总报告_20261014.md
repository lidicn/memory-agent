MA49、MA52、MA54、MA55、MA63、MA71、MA72、MA74、MA75、MA79、MA86、MA88
> **形态**：`except: pass` / `continue` / `print`；成功与失败对外逐字同形。

MA49、MA63、MA69、MA75、MA77、MA79、MA85、MA88、MA89 + **MA-GAP-017**

## 八、全程必须说清的局限（逐轮声明的汇总）

1. **几乎所有盘面都是构造的**：真实 Store / 真实 SQLite / 真实 httpx / 真实 openai SDK + 本地 HTTP 服务，但**数据与响应体是编造的**。真实触发源（HA 429、MariaDB `wait_timeout`、库损坏、固件改格式、供应商限流）**均为推断，未复现**。定 high 的依据是"静默 + 不可区分 + 有可达路径"，**不是已观测线上事故**。
2. **判据大量不在 outcome**：42 条缺陷中绝大多数两侧 outcome 逐字相同，差异只在"报没报"。只比返回值会得出"补丁无效"。
3. **未跑项目自带测试**：`.gates/` 只有 pyflakes 基线，pytest 依赖补装后仍 collection error。全程有效背书是：`py_compile` 双侧 OK + N 组双侧对照 + 反向用例零告警 + 噪声检验（连跑两次逐字段 SAME）+ 125~388 个共同 `.py` 行尾不等价 0 + 基线侧新码命中 0。**不是全绿**。
4. **沙箱补装不代表 CI**：starlette / bcrypt / python-jose / pymysql / mcp 等均在沙箱内补装且多次"装过又消失"。
5. **每轮实测覆盖面窄**：典型形态是"N 组双侧只实测 1 处，其余 M 处读码分类"。按历轮经验比例，静态候选约 15 出 1。
6. **9 个轮次未执行**，其技术表述不采信；**台账 `round` 字段类型混用**，按轮次聚合会漏。
7. **基线树一行未改**，所有补丁只在 `ma_patched`；`ma_new` 无 `.git`，补丁脚本曾写坏 `runtime.py`（靠 diff + patch 脚本重建，见 MA-SELF-007）。
