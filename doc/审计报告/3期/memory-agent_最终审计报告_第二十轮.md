**判为假阳性（3 条）**：

### R5 · NUM-02 `alert_dispatcher.py:34` —— 不可达

直接构造 `_recent = {"s2": {}}` 确实抛 `ValueError: max() arg is an empty sequence`。

**但真实路径不可达**：`setdefault(session_id, {})` 之后紧接着必插一条 alert。实测 300 次 `should_send` 后，4 个存活会话**各有 ≥1 条** ⇒ 空 dict 无法出现。

判为防御性隐患，不立缺陷。

> 这里顺序很关键：**先构造、再证伪**。只跑第一步就报缺陷，会凭空造出一条。

### R6 · GOD-01 `negative_samples.py:229` —— 守卫与危险动作无关

规则认为 `collect_negative_samples()`（L229）排在护栏 `sanitize_text()`（L248）之后。**实际两者操作不同数据**——前者取样本，后者在循环里清洗簇名，无顺序依赖。

规则只看"同函数体内两个调用的先后"，不看数据流 ⇒ 误判。与 W62/W100 同源。

### R7 · FO-01 `candidate_promotion.py:1283` —— 实为 fail-closed

`check_promotion_criteria` 在 except 里 `return False`——**False 的含义是"不晋升"，即保守拒绝**，与失败开放正好相反。

规则只看"异常后返回了值"，**看不出返回值的语义方向**。与 doubao-butler `_butler_patch` 那条 `return res is not None` 同类。
