## 🔍 审计中新发现的未修复问题

### 1. `InsightService.reload_config` 不重建 Repository
- **位置**: `runtime.py:850` 仅 `self.insights.config = self.config`
- **问题**: `InsightService.__init__` ( `insights/api.py:110` ) 在构造时 `build_repository(store, self.config)`，热更新配置后 `repo` 仍持有旧配置（如 `cache_ttl`、`default_days`），导致查询行为与新配置不一致。
- **建议**: 在 `reload_config` 中重建 `self.insights.repo` 并刷新 `resolver`。

### 2. `_safe_entities()` 静默降级仍在
- **位置**: `insights/api.py:133-140`
- **问题**: 虽已改 `LOG.exception` 记录完整堆栈，但仍 `return []`，**上游无感知**。实体目录为空会导致 `EntityResolver` 解析全失败，进而使自然语言查询、行为洞察、设备用量统计全部返回空结果 —— 这正是 P0-1 长期隐匿的根因。
- **建议**: 抛出异常或提供健康检查端点暴露实体加载状态；至少在 `health()` 中返回 `entities_loaded: false`。

### 3. `tool_schema.py` 中 `service="store", method=""` 的工具仅走 MCP 手写实现
- **工具**: `get_device_usage_summary`、`get_room_behavior_summary`、`get_member_daily_pattern`、`query_unified_events`
- **现状**: `generated=False`，`dispatch()` 会因 `getattr(svc, "", None)` 返回 `None` 而报错，但这些工具仅对内置 LLM（`builtin`）暴露，**实际仅通过 MCP 手写 `@mcp.tool()` 注册**。
- **风险**: 若未来启用 `builtin` 调用这些工具会失败；文档与实现割裂。

### 4. Store 部分查询方法未显式加锁
- **现象**: 336 处 `execute/commit` 仅 120 处 `with self._lock:`，需逐方法审计是否有“先连接后释放锁再执行”的模式。
- **样本**: `query_events` (line 3616)、`count_events` (line 3643) 等大查询是否全程持锁需确认。

### 5. `mcp_server.py` 动态注册工具失败仅警告
- **位置**: `mcp_server.py:3054-3062`
- **问题**: `register_simple_tools` 单工具失败只 `logging.warning` 继续，导致 `TOOL_CATALOG` 里有但 `mcp_server` 真无此工具 —— 目录一致性测试可能通过（检查模块属性），实际调用报 `NOT_FOUND`。
