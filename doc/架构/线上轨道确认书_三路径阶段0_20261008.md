## 一、确认项 1：线上容器走 insights/ 还是 insights_legacy.py？

**结论：走 `insights/` 包（新引擎），`insights_legacy.py` 是兼容层。**

### 证据

| 证据点 | 位置 | 说明 |
|---|---|---|
| MCP 工具注册 | `tool_schema.py` 全量 | 93 个 ToolSpec 中，service="insights" 的占绝大多数，method 指向 `insights/api.py` 或 `insights/service.py` |
| route_question 实现 | `insights/api.py:859` | `plan_question()` 调用 `self.nl.plan()`，nl = `insights/nlquery.py` |
| 其他模块引用 | `activity_inference.py`, `config.py`, `templates.py`, `summary_queries.py` | 全部 `from .insights...` import，无 `from .insights_legacy` |
| legacy 自身依赖 | `insights_legacy.py:61-88` | 内部 import `insights.utils` 的 KEYWORD_DOMAINS / OFF_STATES / is_off_state / DEFAULT_DEBOUNCE_SECONDS 等——legacy 是依赖新包的兼容层，不是独立轨道 |
| insights/ 包结构 | 13 个 .py 文件 | api.py(56KB) / service.py(77KB) / repository.py(52KB) / utils.py(49KB) / models.py(21KB) / activity.py(19KB) / anomaly.py(15KB) / nlquery.py(14KB) / parser/ 等 |

### 风险判定

- **无双轨混淆**：线上主轨道是 `insights/`，`insights_legacy.py` 是遗留兼容层且自身依赖新包，不会出现"动了新轨道但线上跑旧轨道"的问题。
- **MVP 改动应落在 `insights/` 包内**，特别是 `insights/api.py`（MCP 工具实现层）和 `insights/nlquery.py`（路由/意图识别层）。

## 二、确认项 2：route_question 实现位置与词典来源

**结论：实现在 `insights/api.py:859`，词典在 `insights/nlquery.py:15`。**

### 调用链

```
MCP route_question(question)
  → mcp_server.py:2951 register_simple_tools 动态注册
  → tool_schema.py:70 ToolSpec(service="insights", method="plan_question")
  → insights/api.py:859 InsightsAPI.plan_question(question, days)
  → insights/nlquery.py:85 NLQuery.plan(question, days)
  → insights/nlquery.py:15 _INTENT_PATTERNS（硬编码元组）
```

### 词典现状

- `_INTENT_PATTERNS`: `Tuple[Tuple[str, str], ...]`，硬编码在 `insights/nlquery.py:15`
- 意图触发词在 `nlquery.py:46` 注释说明"与 `_INTENT_PATTERNS` 的交替项同集合，长串在前由排序保证"
- **词典是静态硬编码的，没有外部化、没有热更新机制**——这正是缺口 C（未命中埋点 + 自动提议）需要解决的问题

### 对 MVP 的影响

- 缺口 A（recipe 回填）和 B（recipe→工具召回）**不需要改 route_question**，它们是路径 3 的回填/召回机制
- 缺口 C（延后）才需要改 `nlquery.py` 的词典机制——从静态硬编码改为可增长的映射表

## 三、确认项 3：add_semantic_memory 的 source_refs 校验位置

**结论：在 `agent_memory.py:90` `_validate_source_refs()`，合法前缀为 event:/insight:/activity:，不支持 recipe:。**

### 校验逻辑

```python
# agent_memory.py:90-106
def _validate_source_refs(self, source_refs: List[str]) -> Tuple[bool, List[str]]:
    VALID_PREFIXES = ("event:", "insight:", "activity:")
    for ref in source_refs:
        if not any(ref.startswith(p) for p in VALID_PREFIXES):
            invalid.append(ref)  # 未知前缀 = 无效
    return (len(invalid) == 0), invalid
```

### 缺口 A 的改动点

- **文件**：`src/memory_agent/agent_memory.py`
- **函数**：`_validate_source_refs`（第 90 行）
- **改动**：`VALID_PREFIXES` 增加 `"recipe:"`
- **配套**：需要 recipe_id 的可解析性校验（对齐 event:/insight: 的"真实可解析"标准），但 DCD 裁定说"真实可解析性在晋升佐证/人工复核阶段校验，故此处不强制实体已存在"——recipe: 也应遵循同口径（前缀格式合法即收，实际存在性在晋升时校验）
