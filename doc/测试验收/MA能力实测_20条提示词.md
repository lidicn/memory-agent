# Memory Agent 能力实测 · 20 条提示词

> 用途：用 opencode 连接 memory-agent 的 MCP（`/mcp`，Streamable HTTP，Bearer 鉴权见 WebUI 接入页）后，逐条粘贴下面的提示词，跑一轮能力实测。
> 每条都标注了「对应能力 / 底层工具」和「怎么算通过」，方便当场判定 MA 是否真的答得出来。
> 提示词可直接复制，无需改字；若你的房间/设备名不同，按表内括号自行替换即可。

---

## 一、入口与设备发现（先确认 MA 看得到你的家）

**P1 · 全屋设备清单**
> 帮我看看家里现在接了哪些智能设备，按房间列一下，顺便说下哪些最近活跃。

- 能力：设备目录 / 人话定位实体
- 工具：`get_entity_catalog(only_enabled=true)`
- 通过标准：返回按房间分组的设备、友好名、`entity_id`、最后在线、近期活跃度；不用你背 `entity_id`。

**P2 · 单房间聚焦**
> 书房里都有哪些设备？给我实体清单就行。

- 能力：房间→实体映射
- 工具：`list_rooms_entities` / `get_entity_catalog(room='书房')`
- 通过标准：列出书房下所有实体及友好名。

## 二、行为洞察（MA 的核心卖点：服务端算好结论）

**P3 · 一周行为总览**
> 过去一周我们家整体的活动规律是怎样的？什么时候最活跃、哪些房间用得多、有没有异常？

- 能力：作息节律 / 房间分布 / 异常检测
- 工具：`get_behavior_insights(days=7)`
- 通过标准：直出活跃时段、各房间 Top 设备、状态转移、异常项（不是几千条原始事件）。

**P4 · 逻辑设备用量（验证 hdmi3 加固）★**
> 客厅电视用「HDMI 3」这个信号源，最近两天一共看了多久？

- 能力：按**逻辑设备名**查询（v0.3 语义工具，entity_id 漂移自愈）
- 工具：`query_device_usage(logical_device='客厅电视', attribute='source', value='HDMI 3', metric='duration', days=2)`
- 通过标准：能返回时长（非 0，且不为空报错）。这条直接验证上一轮把 `xbox` 模板改走 `logical_id='lidcn的电视电视'` 的加固——HA 重登后 entity_id 变了也能算出来。
- 失败信号：`ok=false` 或 `duration=0` 且无解释 → 加固失效，需回查 `run_query` 解析链路。

**P5 · 单设备开关时长**
> 书房空调最近 7 天开了多久、开关了几次、平均每天用多少？

- 能力：设备用量统计（去抖 + 跨窗口截断）
- 工具：`get_device_usage(query='书房空调', days=7)`
- 通过标准：总时长、开关次数、平均单次时长、每日分布、时间线齐全。

**P6 · 空调温感会话**
> 主卧空调最近一周每晚设定几度、室温多少、实际开了多久？

- 能力：climate 会话（设定温 + 室温 + 运行时长拼接）
- 工具：`get_climate_sessions(query='主卧空调', days=7)`
- 通过标准：每条会话含设定温度、室温、运行时长（缺温度会注明原因，不算崩）。

**P7 · 活动识别**
> 这周家里都在做什么？比如做饭、洗澡、看电视、睡觉、离家这类活动，帮我识别出来并给证据。

- 能力：语义活动识别（规则引擎）
- 工具：`infer_activities(days=7)`
- 通过标准：返回各活动每天发生记录 + 置信度 + 证据，而不是原始动线。

**P8 · 自定义活动（教系统新行为）**
> 帮系统记住一个新活动「午休 nap」：工作日下午 1 点到 3 点，卧室有人且安静就算午休。注册好之后，用最近一周数据跑一遍看看识别到没有。

- 能力：Agent 教系统识别新行为
- 工具：`define_activity(name='nap', room='卧室', tags=['presence'], start_hour=13, end_hour=15, ...)` → 再 `infer_activities(activities=['nap'])`
- 通过标准：先返回规则已注册，再返回 nap 的识别结果（哪怕 0 次，也说明规则生效）。

**P9 · 用户滚动画像**
> 根据最近两周的数据，给我画一个用户生活习惯画像：几点睡、爱待哪个房间、媒体/做饭偏好。

- 能力：聚合行为画像
- 工具：`get_user_persona(days=14)`
- 通过标准：活动聚合（出现天数/频次/时段/房间/置信度）+ 房间活跃度。

**P10 · 行为环比**
> 和上周相比，这周家里的活动有什么变化？哪些多了、哪些少了？

- 能力：时段对比 / 趋势
- 工具：`get_behavior_insights_compare(compare_days=7)`
- 通过标准：给出两个首尾相接窗口的 delta 与趋势摘要。

## 三、事件检索（需要原始数据时）

**P11 · 语义搜索 + 摘要**
> 帮我找一下最近客厅里媒体相关的设备变动，做个摘要就行，别列原始数据。

- 能力：语义过滤 + 摘要压缩
- 工具：`search_events(room='客厅', category='media', summarize=true)`
- 通过标准：返回「每个设备变了多少次、变成什么、24h 分布」的摘要 + 样本，带 `total/has_more`。

**P12 · 精确原始事件**
> 把书房最近 2 天所有事件原始列出来，确认有没有取全（我要看分页有没有到底）。

- 能力：精确查询 + 分页完整性
- 工具：`query_events(days=2, rooms=['书房'], limit=500)`
- 通过标准：返回 `total / has_more / next_offset`，据此判断取全没有。

**P13 · 最后状态变化**
> 客厅电视最后一次被关掉是什么时候？

- 能力：最后状态翻转查询
- 工具：`get_last_event(entity_id/room='客厅', transition='off')`
- 通过标准：返回最近一次 off 的时间与上下文。

## 四、数据健康（避免误判空白窗口）

**P14 · 覆盖与质量**
> 最近 7 天里，哪些天其实根本没采到数据？另外整体数据质量有没有问题（重复、单位冲突之类）？

- 能力：数据覆盖报告 + 质量巡检
- 工具：`get_data_coverage(days=7)` + `get_data_quality(days=30)`
- 通过标准：明确列出 `missing_days`；质量侧给出 `data_quality_issues` 清单（空也算正常）。

**P15 · 失联设备**
> 有没有设备失联了、或者没电一直没动静的？重点看那些被模板引用的。

- 能力：设备健康探测
- 工具：`get_device_health(stale_days=3)` / `list_device_health(state='stale')`
- 通过标准：分 `healthy / no_data / stale` 三类，且标出 `referenced=1`（被引用、优先修）。

## 五、家庭成员与生活习惯档案

**P16 · 成员总览**
> 家里现在有哪些家庭成员？各自关联了哪些房间、有没有存生活习惯标签？

- 能力：成员列表
- 工具：`list_members()`
- 通过标准：返回成员 + 关联房间/设备 + 已存档标签。

**P17 · 建成员 + 绑定 + 推断标签**
> 新建一个成员「爸爸」，头像用 🦉；把主卧和书房关联给他。然后基于最近两周数据推断他是不是夜猫子、爱不爱做饭，把证据列出来**问我是否存档**（不要擅自写回）。

- 能力：成员 CRUD + 画像 + 受控标签写回
- 工具：`create_member` → `assign_member_room` → `get_member_persona(days=14)` → `confirm_member_tag`（仅在你确认后）
- 通过标准：成员建好、房间绑定；画像给出候选标签与证据；**未经你确认 MA 不调用 `confirm_member_tag`**。

## 六、自然语言问答与可解释性

**P18 · 口语问答**
> 昨天谁在家做饭了？上周三晚上家里在干嘛？

- 能力：口语→结构化工具映射（关系库主力）+ 向量副驾
- 工具：`ask_memory(question='昨天谁在家做饭', days=7)`
- 通过标准：用自然语言回答案件，而非报错；模糊问法能回落语义检索。

**P19 · 证据溯源**
> 你刚才说用户爱看电视，凭什么？把支撑这个结论的底层事件证据调出来给我看。

- 能力：洞察可解释性
- 工具：`explain_insight(insight_id=...)`（id 来自 P7 的活动 id）
- 通过标准：返回底层触发事件 + `source_refs` 解析，能追溯到具体事件。

## 七、视觉：用自然语言「看」摄像头

**P20 · 看一眼客厅**
> 看看客厅现在有没有人、有没有异常（比如灯亮着没人、或者门口有快递）？

- 能力：视觉识别（取帧 + 多模态描述，隐私优先不返图）
- 工具：`list_vision_cameras()` → `analyze_camera(room='客厅', prompt_preset='people'|'security'|'object')`
- 通过标准：返回**文字描述** `description`；`ok=false` 时给出 `error`（流名错/凭据未配）。如需图片才 `include_preview=true`。

## 八、进阶（Agent 记忆闭环 / 技能 / 运维，可选压测）

> 这几条偏「系统级」，不是日常问答，但能验证 MA 的记忆写回与自学习是否真闭环。

**A1 · Agent 记忆写回闭环**
> 把你刚挖到的洞察「用户工作日 23 点后入睡」先自检一下（dry_run），确认没冲突再晋升成长期记忆，最后用相似问题把它检索回来。

- 能力：参与式记忆（staging→live→检索）
- 工具：`add_semantic_memory(dry_run=true)` → `promote_memory` → `retrieve_agent_memories(question='用户几点睡')`
- 通过标准：dry_run 返回自检结果；晋升后可被检索命中；假 `source_refs` 会被拒。

**A2 · 技能真源同步**
> 列一下网关上现在有哪几个 skill、分别什么版本；再单独拉取 `insight` 这个 skill 的最新内容看看。

- 能力：技能唯一真源
- 工具：`list_skills()` → `get_skill(name='insight')`
- 通过标准：返回 skill 名 + version + updated_at；`get_skill` 回正文。

**A3 · 采集与存储健康**
> 现在采集任务跑到哪了？关系库和向量库状态分别怎样？

- 能力：运维可观测
- 工具：`get_collect_status()` + `trigger_incremental_collection(since_minutes=60)`（可选补采）
- 通过标准：返回采集进度 + 关系库（主）/ 向量库（辅）双层状态。
